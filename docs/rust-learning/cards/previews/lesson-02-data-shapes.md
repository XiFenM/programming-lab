## 01. numel 是 32 位无符号整数，值为 544,997,376。C 里写 uint64\_t nbits = numel \* 16;，Rust 里写 let nbits: u64 = numel \* 16;。两边各发生什么？Rust 为什么这样设计，代价是什么？

类型：技术问答 · 层级：机制 · 等级：A

选入理由：对比 C 的隐式整数转换陷阱，是 C/C++ 背景的面试者常被问到的题。

### 答案

**结论**：C 能编译并悄悄算错，Rust 直接拒绝编译：不同数值类型之间没有隐式转换。

- **C**：先在 32 位里乘，溢出后才扩成 64 位，得到 130,023,424 而不是 8,719,958,016；开了 -Wall -Wextra 也没有警告。
- **Rust**：报类型不匹配，必须写出在哪个宽度里算：u64::from(numel) \* 16，或者 numel as u64 \* 16。
- **代价与惯例**：代价是每次变宽度、变符号都要写出来。惯例是尽早统一成一种类型，长度、下标、偏移全用 usize，因为下标只接受 usize。

**边界**：as 总能编译，放不下时不报错；u64::from 只在不丢信息的方向上存在，方向写反了编译不过。

### 锚点

没有隐式数值转换；在哪个宽度里算要写出来

## 02. Rust 里整数运算溢出时会发生什么？分别说明写死的常量、调试构建、发布构建三种情况，并和 C 的规则对比。为什么调试时检查、发布时不检查？

类型：技术问答 · 层级：机制 · 等级：A

选入理由：“Rust 的整数溢出是不是未定义行为”是经典面试题。

### 答案

**结论**：溢出不是未定义行为，而是有明确规定的程序错误：调试构建 panic，发布构建默认按补码回绕。

- **三种情况**：常量溢出如 1u32 - 2 直接是编译错误；运行时才知道的值，调试构建 panic，发布构建只留下低位、不报错。
- **和 C 对比**：C 的有符号溢出是未定义行为，编译器可以假设它不发生；Rust 里有符号、无符号是同一条规则。
- **为什么**：语言把溢出定性为程序员的错误：开了调试断言的构建必须检查并 panic，其他构建由实现决定，回绕时结果必须是确定的二进制补码。Cargo 默认调试开、发布关，省掉的是每次运算后的一次判断。

**边界**：推论：默认的发布构建里溢出是静默的，回绕出的数是错的，但不会报错。

### 锚点

不是 UB：调试 panic，发布回绕且静默

## 03. 程序要根据外部文件头里的 shape 和每个元素的位数，算出一个张量占多少字节。文件是别人给的，不可信。这个乘法应该怎么写？checked\_\*、wrapping\_\*、saturating\_\* 三组方法各用在什么场合？

类型：技术问答 · 层级：机制 · 等级：A

选入理由：防止用不可信输入算大小时的溢出漏洞，是系统岗位常见的安全题。

### 答案

**结论**：用 checked\_mul：溢出时得到 None，把溢出变成一个调用方必须处理的值。

- **为什么**：默认的发布构建里普通的乘法溢出后静默回绕，算出一个看起来正常的数。checked\_\* 返回 Option，不把它拆开就用不了里面的数，调用方没法忽略。
- **另外两组**：wrapping\_\* 明确要回绕，用在回绕本身是算法一部分的地方，例如哈希；saturating\_\* 卡在上下限。
- **真实代码**：safetensors 校验文件头时用 checked\_mul 把各维连乘，再乘位数，溢出就返回校验错误。64 位的 usize 让真实模型不会溢出，checked\_mul 防的是恶意文件头，比如把 shape 写成两个 2 的 40 次方。

**边界**：减法同理：止小于起时 end - start 会溢出，用 checked\_sub，或者像 safetensors 那样先比较再减。

### 锚点

不可信输入的大小计算用 checked\_\*，让溢出变成 None

## 04. Rust 的切片 &\[T\] 为什么设计成“指针加长度”两个机器字？对比把长度留在类型里的数组，以及 C 的数组传参，说明它解决了什么问题、付出了什么。

类型：技术问答 · 层级：机制 · 等级：A

选入理由：“&\[T\] 是什么、为什么是胖指针”是基础面试题。

### 答案

**结论**：它让一个函数能处理任意长度的一段元素，同时长度永远跟着指针，每次下标访问都有东西可比。

- **长度留在类型里**：数组 \[T; N\] 的长度是类型的一部分，接收 \[i32; 5\] 的函数传 \[i32; 4\] 就编译不过，每种长度是一个不同的类型。
- **C 的做法**：数组传参退化成指针，长度丢了，要靠另一个参数传，两者对不对得上没人检查；把 4 个元素的数组传给要 5 个的函数能编译，运行时读到数组之外。
- **Rust 的做法**：把那对指针和长度做成一个值；取子切片只算出一个新指针和一个新长度，不复制元素。
- **代价**：引用占 16 字节而不是 8，每次按下标访问多一次比较；用 for 逐个遍历不经过下标，没有这次比较。

**边界**：切片只能表示连续的一段，步长视图和多维视图表示不了。

### 锚点

长度跟着指针走：任意长度可传，下标可检查

## 05. Rust 里 \[T; N\]、Vec&lt;T&gt;、&\[T\] 都表示“一串元素”。它们有什么区别？分别说明长度何时确定、值里放的是什么、是否拥有数据，以及函数参数通常该写哪一种。

类型：技术问答 · 层级：原子 · 等级：A

选入理由：三者的选择是日常编码和面试都会问到的基础判断。

### 答案

**结论**：数组的值就是元素本身；Vec 拥有堆上的数据；切片只是借来的指针加长度。

- **\[T; N\]**：长度在编译期确定并写在类型里，值里就是 N 个元素。
- **Vec&lt;T&gt;**：长度运行期可以增长，值里是指针、容量、长度，64 位机器上共 24 字节，数据在堆上并归它所有；从别处的数据造一个就要复制。
- **&\[T\]**：值里是指针和长度共 16 字节，不拥有数据，是借别人的。
- **函数参数**：写成 &\[T\]，数组和 Vec 都能传进来，也不发生复制。

**边界**：要自己保存运行时才知道长度的数据用 Vec；只是看一段已有的数据用切片。

### 锚点

数组是元素本身，Vec 拥有堆数据，切片只借

## 07. Rust 里 &i32 是 8 字节，&\[i32\] 和 &str 是 16 字节。这种多带一个字的胖指针，多带的那个字一定是长度吗？它由什么决定？和 C++ 存放虚表指针的方式有什么不同？

### 答案

**结论**：不一定是长度：它是什么由指针指向的类型决定，带的是那个类型在编译时缺的信息。

## 10. struct Plain { a: u8, b: u32, c: u8 } 在 C 里占 12 字节，Rust 1.97.1 默认只占 8 字节。Rust 做了什么？它为什么敢这样做？这带来哪些限制，需要和 C 或文件格式对接时怎么办？

## 11. C 里表示“几选一”的数据，通常用一个 enum 标签加一个 union。这种写法有哪三个洞？Rust 的 enum 分别怎样堵上？

类型：技术问答 · 层级：机制 · 等级：A

选入理由：“Rust 的 enum 比 C 的枚举多了什么”是这一课的中心问题，也是常见面试题。

### 答案

**结论**：C 的标签和数据只是靠约定配合；Rust 把标签和载荷做成一个类型并且绑死。

- **不一致**：C 里标签和载荷可以不一致：标签说是点击，载荷里放的却是按键，读出来是错的数据，没有任何警告。Rust 的载荷只能在 match 的对应分支里拿到。
- **漏分支**：C 的 switch 漏了分支最多只有一条警告。Rust 的 match 必须穷尽，漏一个变体是编译错误。
- **任意整数**：C 里任何整数都能当枚举值。Rust 的整数不能转成 enum，标签只会是声明过的那几个变体。

**边界**：代价是每个值按最大的变体占空间；写下划线兜底会放弃加变体时编译器的提醒。

### 锚点

标签与数据绑死；match 穷尽；整数不能当枚举

## 12. Rust 1.97.1、64 位机器上，Option&lt;u32&gt; 是 8 字节，Option&lt;Box&lt;u32&gt;&gt; 也是 8 字节，Option&lt;bool&gt; 只有 1 字节。enum 的值多大是怎样决定的？这三个大小各怎么解释？

类型：技术问答 · 层级：机制 · 等级：A

选入理由：“Option&lt;Box&lt;T&gt;&gt; 为什么和裸指针一样大”是高频面试题。

### 答案

**结论**：大小等于最大的变体加标签，再按对齐凑整；当载荷有永远用不到的取值时，编译器把标签藏进去，不再单独占字节。

- **Option&lt;u32&gt;**：u32 的每一种取值都是合法的数，没有哪个能空出来表示“没有”，所以要另外放 4 字节的标签，共 8 字节。
- **Option&lt;Box&lt;u32&gt;&gt;**：Box 里是一个一定有效的地址，永远不会全是 0，编译器就拿全 0 表示 None，仍是 8 字节。内存里和 C 的可空指针一模一样。
- **Option&lt;bool&gt;**：bool 只用 0 和 1 两个取值，2 就可以表示 None，所以只占 1 字节。

**边界**：这只是编译器省空间的做法，对写代码没有影响：仍然必须先确认是哪个变体，才能拿到里面的值。

### 锚点

最大变体加标签并凑整；有空闲取值时标签不占地方

## 13. Rust 不允许用 e.0 这样的写法直接取出 enum 值里的数据。为什么？拿到载荷有哪几种写法，各适合什么情况？以后给 enum 加变体时，它们的表现有什么不同？

类型：技术问答 · 层级：机制 · 等级：A

选入理由：match、if let、let else 的取舍是常见面试题。

### 答案

**结论**：要拿到载荷，必须经过一个写明变体的模式：判断是哪个变体和取出数据写成一步。

- **为什么不给 e.0**：一个 enum 值里有哪些字段，取决于运行时它是哪个变体。e.0 里没有地方写“我认为它是哪个变体”，要么不检查，那就是 C 的 union；要么运行时偷偷检查、不对就崩。Rust 两条都不走。
- **四种写法**：每个变体各做各的用 match；只关心一个变体用 if let；不是这个变体就提前返回用 let … else；只要一个布尔结果用 matches!。

判断变体和取数据是同一步；简写不做穷尽检查

## 16. 读取一个值内部的数据，Rust 有字段访问（如 rect.top\_left.y）、解构（如 let (start, end) = offsets;）和嵌套模式三种写法。它们各适合什么情况？嵌套模式怎样把 match 套 match 压平？

类型：技术问答 · 层级：机制 · 等级：B

### 答案

**结论**：有名字的字段直接访问；没有名字的位置用解构起名字；要同时判断好几层的形状时用嵌套模式。

- **字段访问**：带字段名的 struct 读几个字段时最直接，名字已经有了。
- **解构**：元组和元组结构体的 .0、.2 看不出含义，解构能起名字；模式里还必须把字段列全，漏了要么补上，要么明确写两个点表示不要。
- **嵌套模式**：WorkerType::Prefill { bootstrap\_port: Some(port) } 一个模式做了三件事：确认是 Prefill，确认端口是 Some，把端口取出来叫 port。原来的 match 套 match 变成并列的分支，穷尽检查照样管用。

## 19. Box&lt;T&gt; 和 &mut T 都是 8 字节的指针，都能修改指向的值，同一时刻也都只有它一个能碰那个值。它们的根本区别是什么？这个区别在哪些地方看得出来？各用在什么场合？

类型：技术问答 · 层级：机制 · 等级：A

选入理由：拥有与借用的区别是 Rust 面试的核心。

### 答案

**结论**：区别在值归谁：Box 拥有它指向的值，&mut 只是把别人的值临时借来改。

- **Box**：值在堆上，归这个 Box；Box 用完，值就释放；它可以从函数返回、存进 struct。
- **&mut**：值在哪里都行，取地址不分配；用完什么都不发生，释放永远是原主的事；它不能比原主存在得久。
- **看得出来的地方**：函数里造的值，Box 能带出来，返回局部变量的 &mut 编译不过。借出去期间原主自己也不能碰；原主销毁之前借用必须已经结束，否则编译不过。
- **怎么选**：值需要一个主人并且要放在堆上，用 Box，常见于字段；值已经有主、只是让别人临时改一下，用 &mut，常见于函数参数。

**边界**：两者不是二选一，可以把 Box 里的值再借出去改。C 和 C++ 里原主销毁后继续用指针通常能编译，只是悄悄读写了已释放的内存。

### 锚点

Box 拥有，&mut 借用；借用不能比原主久

## 22. Rust 里 for s in &self.shape { n = n.checked\_mul(\*s)?; } 这一行，为什么 shape 前面要写 &，s 前面又要写 \*？用“值本身还是地址”的模型，解释 & 和 \* 各做了什么，以及什么时候不用写 \*。

### 答案

**结论**：u32 和 &u32 是两个不同的类型：前者是数本身，后者是指向它的地址。& 取地址，\* 顺着地址读出值。

## 28. Rust 里 #\[derive(PartialEq)\] 已经能用 ==，为什么还有一个 Eq？它多了什么？为什么带 f32 字段的类型不能 derive Eq？

## 32. 从一个字节缓冲区里取出从 start 到 end 的一段，可以写 &data\[start..end\]，也可以写 data.get(start..end)。两者在检查上有什么区别？各用在什么场合？

类型：真实纠错 · 层级：原子 · 等级：A

选入理由：处理不可信范围时选错写法会让服务 panic；这也是课上的真实误解。

### 场景

第 02 课结课前的答疑：练习里 slice 手写的三个比较可以换成 get。

### 正确

两者做的是同一个检查，区别只在检查不通过之后：下标 panic，get 返回 None。

### 错误

所以data.get相比于直接的\[start,end\]，可以多给出异常情况的检查，异常时返回None是吧？

### 说明

**结论**：返回 None 是对的，“多了检查”不对：下标访问同样会检查起止颠倒和越界。

- **手写比较**：先手写几个比较再用下标，等于同一个检查做了两遍，而且容易在大于等于和大于之间差一。

**边界**：两种写法都会在越界时拦住，只是拦住之后的行为不同。

## 33. 看了几个含指针的 Rust 类型，它们的大小都是 8 的倍数。是不是所有类型的大小都按 8 对齐？一个类型的对齐和大小是怎样决定的？

类型：真实纠错 · 层级：机制 · 等级：B

### 场景

第 02 课看了图解页里几个 enum 的字节之后的追问。

### 正确

不是；对齐取字段里最大的那个对齐，大小是对齐的整数倍。全是 u8 的 struct 对齐是 1。

### 错误

我发现这些内存都是对齐8的。所以大小都是对齐8吗？

### 说明

**结论**：对齐是 8 的只是含有指针、usize 或 u64 的类型。

- **三条规则**：每个基本类型有自己的对齐，一般等于它的大小；复合类型的对齐等于它的字段里最大的那个对齐；大小是对齐的整数倍。
- **例子**：三个 u8 字段的 struct 是 3 字节、对齐 1；一个 u16 加一个 u8 是 4 字节、对齐 2；一个 u8 加一个 \[u32; 100\] 是 404 字节、对齐 4，比的是对齐而不是大小。
- **为什么凑整**：为了放进数组：第 i 个元素在偏移 i 乘大小处，大小是对齐的整数倍，每个元素才都落在对齐的地址上。

**边界**：“基本类型的对齐等于它的大小”是平台的规定，不是语言的规定；判断时看对齐，不要拿大小代替。

## 35. 一个 enum 以后要加新的变体。对它做 match 时，逐个列出所有变体和用下划线兜底这两种写法，在加变体之后各会发生什么？下划线是不是“至少有个兜底”？

### 场景

第 02 课节点 5–6 的检查题：给请求状态加一种“已取消”。

### 正确

逐个列出的 match 会编译失败并指出没处理的变体；带下划线的照常编译，新变体被悄悄归进“其余”，而那个兜底对它未必正确。

### 错误

### 说明

## 40. 面试官说：“C 里我用 (const uint8\_t \*p, size\_t len) 传一段数据，用可空指针 T \*p 表示‘可能没有’。Rust 里这两样分别对应什么类型？内存里变大了吗？Rust 多保证了什么，代价是什么？”请用 60–90 秒回答。

类型：综合口述 · 层级：综合口述 · 等级：A

选入理由：这就是综合验收的口述题，直接对应“Rust 相对 C 多保证了什么”的面试问法。

### 参考回答

**结论**：一段数据对应切片 &\[u8\]，可空指针对应 Option 包住的引用或 Box；内存没有变大，多出来的是保证。

- **对应与大小**：切片就是指针加长度两个字，16 字节；引用和 Box 不会为 0，编译器拿 0 表示 None，Option 包一层仍是 8 字节。
- **多保证了什么**：长度永远跟着指针，每次下标访问都会检查；“没有”写进了类型，不先处理 None 就拿不到里面的值。
- **代价**：运行时每次下标访问多一次比较，代码里必须写出处理 None 的分支；编译期的检查不花运行时间。

**边界**：越界检查在发布构建里也不关；逐个遍历不经过下标，没有这次比较。

### 评分锚点

- 说出切片是指针加长度、16 字节，与 C 的一对参数一样大
- 说出 Option 包住引用或 Box 不增加大小，以及原因
- 说明多出的两项保证：长度被绑定并检查、必须先处理 None
- 把代价归到运行时的边界检查和必须写的分支，而不是编译器检查

## 41. 请用 60–90 秒向面试官讲清：Rust 的 enum 和 C 的 enum 加 union、C++ 的 std::variant 相比，内存里长什么样，多了哪些保证，付出了什么代价？

类型：综合口述 · 层级：综合口述 · 等级：A

选入理由：“Rust 的 enum 比 C 的枚举多了什么”是这一课最可能被问到的整体题。

### 参考回答

**结论**：Rust 的 enum 是带标签的联合：每个变体可以带自己的数据，标签和载荷绑死，数据只能在匹配到对应变体时取到。

- **布局**：内存里是标签加最大变体那么大的空间，按对齐凑整；载荷有用不到的取值时标签藏进去，所以 Option 包住 Box 不占额外空间。
- **相对 C**：C 的标签和 union 靠约定配合，可以不一致，switch 漏分支只有警告，任何整数都能当枚举值；Rust 里这三件事分别是做不到、编译错误、不允许转换。
- **相对 C++**：std::variant 思路相同，但取错成员要到运行时才抛异常，漏处理一种情况报的是模板错误。
- **代价**：每个值按最大的变体占空间；写下划线兜底会放弃加变体时编译器的提醒。

**边界**：取载荷必须经过写明变体的模式，这次检查省不掉；标签怎样摆放是编译器的选择。

### 评分锚点

- 说出布局：标签加最大变体，标签可以藏进用不到的取值
- 对比 C：标签与数据不一致、漏分支、任意整数这三个洞及 Rust 的做法
- 对比 std::variant：取错成员的发现时机，或漏分支的报错方式
- 说出两条代价：按最大变体占空间、下划线兜底关掉提醒
- 指出取载荷必须经过模式

## 42. 面试官问：你的 Rust 服务要解析别人给的模型权重文件，文件头里的 shape 和偏移都不可信。用这些数算大小、取数据时，Rust 在哪些地方会帮你，哪些地方仍然要自己小心？请用 60–90 秒回答，并举出一个会出事的具体输入。

类型：综合口述 · 层级：综合口述 · 等级：A

选入理由：把这一课的数值规则落到权重文件解析的真实场景，贴近 AI 基础设施岗位。

### 参考回答

**结论**：越界读写 Rust 一定拦得住；但整数溢出在发布构建里是静默的，as 的截断任何时候都是静默的，这两处要自己用检查过的运算。

- **溢出**：调试构建溢出会 panic，发布构建默认回绕成一个错的数；所以大小和偏移的计算用 checked\_mul、checked\_sub 这类运算，把溢出变成必须处理的 None。
- **会出事的输入**：一个声称有 2 的 61 次方加 3 个 u8 元素的张量，乘 8 位后回绕成 3 字节，和偏移给的长度正好对上，就被当成正常数据接受。
- **类型转换**：把 usize 的偏移用 as 转成 u32 不会报错，文件超过 4 GiB 时悄悄截断。
- **取数据**：范围来自外部时用 get，越界和起止颠倒得到 None，而不是让服务 panic。

**边界**：普通的坏输入回绕后往往碰巧被拒绝，测试会全部通过；要专门构造回绕后对得上的输入，并在发布构建下跑测试。

### 评分锚点

- 区分调试构建 panic 与发布构建静默回绕
- 说出用 checked 系列运算把溢出变成 None
- 指出 as 的截断不受溢出检查保护
- 举出回绕后被接受的具体输入或同类例子
- 说明取数据时 get 与下标的取舍，以及测试要覆盖发布构建
