把等待叠进计算

持久化把 tile 之间的交接放进了同一段代码，但交接处的等待还在。flatten 让编译器把“tile 循环套 K 循环”合成一层，软件流水于是能跨过 tile 的边界：下一个 tile 的数据，在当前 tile 还没算完时就已经上路。

合并之前，流水每个 tile 重新预热一次；合并之后，整个 CTA 只预热一次。代价是 epilogue 写回时输入缓冲还被占着，共享内存要多留一块。

全页沿用课上的例子：M = N = 8192、K = 512、fp16；块是 128 × 128 × 64，所以每个 tile 的 K 循环是 8 轮，下面记作 n；num_stages = 3，记作 S，意思是读入比乘加提前 2 轮。编译数字来自 sm_89，B 按教程 benchmark 的传法（b.T）。

前置

两个前置概念

都是普通的循环改写，用 C 就能写出来。编译器做的是同样的事，只是自动完成。

A软件流水

一轮循环有两步：发出读入，用数据计算。流水是把第一步提前：算第 k 轮时，第 k+2 轮的数据已经在路上。数据要有地方放，所以要 S−1 个轮换使用的缓冲槽。第 02 课的 num_stages 就是它。

// S = 3：读入比计算提前两轮，两个缓冲槽轮换
start_load(slot[0], 0);   // 预热：循环开始之前
start_load(slot[1], 1);   // 先发出头两轮的读入
for (k = 0; k < n; k++) {
    wait_arrived(slot[k % 2]);   // 等第 k 轮的数据到齐
    compute(slot[k % 2]);        // 乘加
    if (k + 2 < n)               // 腾出的槽马上给后面用
        start_load(slot[k % 2], k + 2);
}

关键限制：流水只在一个循环内部生效。循环一结束，在路上的东西就清空了；下次再进这个循环，要重新预热。

B循环合并

两层循环可以改写成一层，办法是加一个计数器 T，记住“现在是这个 tile 的第几轮”。T 为 0 时顺手做外层开头的事，T 到末尾时做外层结尾的事。

// 两层
for (i = 0; i < tiles; i++) {
    prologue(i);
    for (k = 0; k < n; k++) body(i, k);
    epilogue(i);
}

// 合成一层
T = 0; i = -1;
for (it = 0; it < tiles * n; it++) {
    if (T == 0)     { i++; prologue(i); k = 0; }
    body(i, k); k++;
    if (T == n - 1) epilogue(i);
    T = (T == n - 1) ? 0 : T + 1;
}

两种写法算的东西完全一样。区别只在形状：下面这种是一个循环，流水可以一直转下去，不会在 tile 之间断开。

代价与条件

多出来的 32,768 字节是什么

epilogue 要把累加器从张量核心的布局换成写回用的布局，这一步借共享内存做中转。本例里中转的大小正好是一个 fp16 的输出块：128 × 128 × 2 = 32,768 字节。不合并时，输入缓冲这时已经用完，中转可以借它们的地方。合并之后，下一个 tile 的读入已经在途，输入缓冲借不了，只能另开一块。

中转的大小不是固定的规律。换一种块或 warp 数，编译器可能把转换分成几批做，每批用同一块更小的中转区：同样是 128 × 128 的块，4 个 warp 时是 16,384 字节；BLOCK_N 为 256、8 个 warp 时是 8,192 字节。

什么时候它不起作用

  • 只认最简单的嵌套：一个外层 for 里正好套一个内层 for。三层不行，两层之间隔着 while 或 if 也不行。
  • 内层的次数默认要在进入外层之前就能算出来。实验：把 K 循环的次数改成随 tile 变化，flatten=True 被忽略，产物与不写它完全相同，没有报错也没有警告。v3.7.1 另留了一条路：用 tl.assume 保证内层至少执行一次，且次数只由外层的循环变量经标量运算得到时，编译器先用一个小循环求出总迭代数，再合并（见“迁移”一节）。
  • 它是请求，不是保证。要确认它生效，看产物：共享内存是否多了一块，IR 里是否出现了 scf.if，预热和排空是否移到了循环外面。怎样看，见“查看产物”一节。
  • Hopper 上不能和 warp 专用化同时用。合并后的循环里有带 else 的 scf.if，Hopper 的 warp 专用化遇到它就放弃。教程第 592 行因此把 flatten 关掉。
  • v3.7.1 的一个边界：B 按普通的行主序 [K, N] 存放时，合并后只有 A 保持异步拷贝，B 变成同步读入。原因是带连续性声明的列偏移变成了 scf.if 的输出，流水挑选读入时取不到这条声明。教程的 benchmark 传入的是 b.T，不受影响。声明为什么会丢、怎样写才保得住，见“声明”一节。

迁移

grouped GEMM 能不能跨 tile 流水

能，但要先把循环改成编译器认得的形状。只把第 08 课的 while 换成 for 不够。

编译器按什么找可以合并的循环

  • 正好两层。带 flatten=True 的 for 必须是这组嵌套的最外层，里面正好有一个 for，再往里没有别的循环。
  • 中间不能隔着别的结构。找循环时遇到 while 或 if 就停下，里面的循环另算一组。
  • 内层的次数要提前知道。默认要求它在进入外层之前就能算出来。次数随外层变化时还有一条路：用 tl.assume 保证内层至少执行一次，并且次数只由外层的循环变量经标量运算（包括读一个标量）得到；这时编译器先用一个小循环把总迭代数加出来。

改成写法 ④ 要一起带上的

  • epilogue 要有自己的游标，并再查一次表。道理和 tile_id_c 相同：prologue 的游标已经提前走到下一个 tile 了。
  • 行列偏移放在 K 循环里算。这是 v3.7.1 的边界：在 tile 开头算出的偏移经过 scf.if 传出后，连续性信息丢失，对应的读入就退回同步。
  • K 循环外面不能再包 if。
  • 代价。共享内存多 32,768 字节；主机多建一张表；每个 tile 多几次标量读表。

边界。这些都是只编译看到的结构，没有在设备上验证数值，也没有测过性能。K 循环越长，跨 tile 流水省下的那一段占比越小；MoE 的 K 是隐藏维度，一个 tile 往往有几十轮，值不值得要实测。写法 ② 的 tile 循环外面再包一层 if，里面两层会被单独合并（98,304），但流水在每个问题的边界仍要重新预热；这是当前实现的副作用，源码里标着待改进，不宜依赖。

为什么 sm_90 要多一个输入槽

每轮搬进来的数据量没有变，都是 A、B 各一块。变的是一个槽要被占多久。下面是 num_stages = 3 时第 k 轮里发生的事。

sm_89先取走，再计算

  1. 等第 k 轮的数据到齐。
  2. ldmatrix 把它从槽里取进寄存器。这个槽空了。
  3. mma.sync 在寄存器上计算。
  4. 发出第 k+2 轮的读入，写进刚空出来的槽。

同时被占的只有第 k+1、k+2 两轮的数据：2 个槽。

sm_90就地读，边读边算

  1. 等第 k 轮的数据到齐。
  2. 发出 wgmma，它直接读这个槽，发出后立刻返回。这个槽还在被读。
  3. 发出第 k+2 轮的读入。第 k 轮的槽不能用，第 k+1 轮的槽里有数据，只能用第三个槽。

同时被占的是第 k、k+1、k+2 三轮的数据：3 个槽，共享内存从 65,536 变成 98,304。

所以槽数取决于乘加是不是就地、异步地读共享内存，和用不用 TMA 无关。sm_120 用 TMA 搬运、用 mma.sync 计算，仍然是 2 个槽。

B 为什么按 [N, K] 存放

  • 沿 K 方向连续。描述符要求最后一维连续。按 [N, K] 存，取出的 B 块在内存里就是沿 K 连续的，这正是乘加指令默认要的摆法（K 为主）。kernel 里用 b.T 表达数学上的 B。
  • fp8 没有转置这个选项。PTX 文档规定，wgmma 的转置参数只支持 fp16 和 bf16。fp16 时 B 按 [K, N] 存也行，指令带一个转置标志就够了；fp8 时编译器只能先把 B 取进寄存器、重排后再存回共享内存。
  • 编译对照（sm_90，描述符版，fp8）：按 [N, K] 存是 90 个寄存器；按 [K, N] 存是 113 个，并多出 32 条逐字节写共享内存的指令。fp16 时两种存法的指令构成相同。

节点 5

warp 专用化：让不同的 warp 各管一件事

不专用化时，同一批 warp 轮流做搬运、乘加和写回。专用化把循环体按角色拆开，分给不同的 warp 分区，每个分区有自己的循环，靠屏障交接。这就是生产者与消费者：共享内存里的输入槽是环形缓冲，每个槽配两个信号，一个表示“数据到了”，一个表示“槽空了”。

目标
  • 乘加分到几个 warp，由那一代的乘加指令决定。mma.sync 每个 warp 只能算自己那一份，所以 sm_120 的乘加留在原来的 8 个 warp 里；wgmma 以 warpgroup 为单位，一条算 64 行，sm_90 用两个 warpgroup 各算一半；tcgen05.mma 一个线程就能发起，sm_100 只分 1 个 warp。
  • 每个分区各拿一份同样形状的循环，里面只留自己的操作。Hopper 上搬运分区仍是 tile 循环套 K 循环，但两个 K 循环之间没有排空，也没有 epilogue，只有下一个 tile 的坐标计算。所以它不会在 tile 的边界停下来，关掉 flatten 并不丢掉跨 tile 的预取。各分区的循环各数各的，只靠屏障对齐。
  • sm_100 上三件事真正并行。持久版在 TMEM 里开了两个累加器（256 列）：默认分区读出并写回上一个 tile 时，下一个 tile 的乘加写进另一个累加器。

“分区”是什么

分区就是 CTA 里一段编号连续的 warp，被指定去跑同一段代码。硬件只认 warp，不认分区；分区是编译器划的。kernel 的入口处，每个线程先算出自己在第几个 warp，再跳到那个分区的循环。用 C 写是这样：

// 12 个 warp、384 个线程都从这里进来，跑的是同一份二进制
int warp = thread_id / 32;
if (warp < 8)  default_partition();      // 默认分区：原来申请的那 8 个 warp
else           jump_table[warp - 8]();   // 其余的 warp 各自跳到自己分区的循环

sm_100 的产物里对应的就是这几行：

.reqntid 384                           // 申请 384 个线程
mov.u32  %r1, %tid.x;
shr.u32  %r2, %r1, 5;                  // 线程号除以 32，得到 warp 号
setp.lt.u32  %p1, %r3, 8;
@%p1 bra  $L__BB0_15;                  // warp 号小于 8：去默认分区的代码
brx.idx  %r9, $L_brx_0;                // 否则按 warp 号查跳转表
setmaxnreg.inc.sync.aligned.u32  24;   // 进了分区先声明：这里每个线程只要 24 个寄存器

“默认分区”特殊在它还负责专用化那段循环之外的代码，例如开头的准备和结尾的写回。别的分区只在那段循环里存在。

节点 6

epilogue 拆半与共享内存的预算

描述符版写回 C 时，要先把整块结果放进共享内存，TMA 再从那里搬走。这块输出缓冲和输入槽争同一份共享内存。把输出切成左右两半、分两次写回，输出缓冲就只要一半，省下的地方可以换成多一级流水。

源码里怎样切成两半

# 教程第 435–442 行
acc = tl.reshape(accumulator, (BLOCK_SIZE_M, 2, BLOCK_SIZE_N // 2))  # 把 N 方向看成“2 段 × 每段 N/2 列”
acc = tl.permute(acc, (0, 2, 1))                                    # 把“段”换到最后一维
acc0, acc1 = tl.split(acc)                                          # 沿最后一维拆成两个 M × N/2 的张量
c_desc.store([offs_am_c, offs_bn_c], acc0.to(dtype))                         # 左半
c_desc.store([offs_am_c, offs_bn_c + BLOCK_SIZE_N // 2], acc1.to(dtype))     # 右半

绕这一圈是因为 Triton 没有“取一个张量的左半边”这种切片，只有 tl.split：沿大小为 2 的最后一维拆开。C 的描述符的块形状也要跟着改成 [BLOCK_M, BLOCK_N // 2]，这由 pre_hook 完成（第 190–193 行）。

练习答疑

取值连续与两条声明

练习里 B 按行主序存放，N 方向的下标一经 tl.where，B 的读入就退回了同步读。这一节说明编译器怎样判断一个下标“取值连续”，tl.where 为什么让这个判断失效，tl.max_contiguous 和 tl.multiple_of 怎样把信息补回去，以及补回去的承诺在边界 tile 里并不成立、却为什么不出事。

编译器不知道下标的具体数值，只记得它能证明的几条性质。一次读入能搬多少字节，由这些性质里最弱的一条决定。声明的作用，是替编译器补上它证明不了的那几条。

两种“连续”

存储连续取值连续
说的是什么张量自己的元素在内存里是不是挨着放张量里存的那些数是不是 v, v+1, v+2, …
本课的例子约定要求 a、b 连续（is_contiguous()）offset_n 是不是 192, 193, 194, …
关心它是因为决定怎样按步长找到每个元素下标指向的地址是不是相邻，能不能一次搬完

tl.where 新建的张量在存储上没有问题，64 个数一个不少地分在各线程的寄存器里。本节说的都是第二种：这些数作为下标去访问内存时，指向的地址相不相邻。

编译器记下的三条性质

这套分析叫轴信息分析（AxisInfo）。它对每个整数张量和指针张量，按维度记三个数，每条操作都有固定的推导规则：

性质含义tid_n * 64 + tl.arange(0, 64)0, 1, 2, 0, 4, 5, 6, 7
取值连续度能切成每组 C 个、组内一路加一的段641
组首整除度每组第一个元素是 D 的倍数，D 取 2 的幂641
恒定度能切成每组 C 个、组内全部相等的段11

右列是源码注释里的例子：中间那个 0 打断了一路加一，取值连续度只剩 1，每个元素自成一组，组首整除度也就只能按 1 算。

读入时，一个线程一次搬几个元素，取下面四项里最小的：

一次搬的元素数 = min( 取值连续度, 组首对齐, mask 的恒定度, 布局分给每个线程的元素数 )

组首对齐由下标的组首整除度、指针基址（Triton 发射时确认它 16 字节对齐）和行步长一起决定。至少要搬 32 bit 才会改成 cp.async，所以 fp16 要搬满 16 字节，就得 8 个元素同时满足四项。

tl.where 的规则

tl.where(cond, x, y) 逐个位置取值，r[i] = cond[i] ? x[i] : y[i]。编译时不知道 cond 是什么样子，于是不知道 r 的哪些位置来自 x、哪些来自 y，只能取三者的最大公约数：

取值连续度(r) = gcd( 取值连续度(x), 取值连续度(y), 恒定度(cond) )

y 是常量 0，所有元素相等，取值连续度是 1。不论 x 多规整，r 的取值连续度都只剩 1，组首整除度也跟着降到 1。这是对任何 N 都必须成立的保守结论，并不是说值真的乱了：完整的 tile 里，值照样一路加一。设 x 是 192 到 199 这 8 个下标，看三种 N：

  • 声明的值也决定一次搬多少：取值连续度或组首整除度写成 4，一次就只能搬 4 个 fp16，也就是 8 字节。

边界 tile 里的承诺为什么不出事

N = 208 时，第 3 号 tile 经过 tl.where 之后是 192, …, 207，再跟 48 个 0。“每 64 个一路加一”在这个 tile 里并不成立。编译器信了声明，对每组发一条 16 字节的拷贝，起点取组里第一个下标。对全是 0 的那几组，它要搬的是这一行的第 0–7 列。这次搬运最终有没有发生、会不会出错，取决于下面三条：

  1. N 是 16 的倍数，编译器才会依赖这条承诺。它只在证明得了地址对齐时才成组地搬。N 不是 16 的倍数时，编译器直接逐元素读，声明根本用不上。
  2. 边界一定落在两组之间，这是上一条自动带来的。每组 8 个元素，组首都是 8 的倍数；N 是 16 的倍数，自然也是 8 的倍数，N 本身就是某一组的组首。所以不会出现半组有效、半组越界。
  3. 越界位置的值不影响结果，这一条要靠写代码的人保证。练习的写法里，mask 在 tl.where 之前计算，全是 0 的那几组 mask 全为假，一个字节也不读（见下面的 PTX）。教程的 B 没有 N 方向的 mask，这些组真的会读第 0–7 列，但读到的值只会算出第 N 列以后的输出，写回时被 mask 丢掉。

cp.async.cg.shared.global [ %r109 + 0 ], [ %rd6 + 0 ], 0x10, %r110;
// 0x10：目标处写 16 字节；%r110：从源地址读多少字节，不足的部分补 0

K 方向不一样：越界位置会进入求和。只有 mask 用改写之前的下标计算、把这些位置读成 0，同样的写法才是对的。练习里的 R-01 就出在这里。还有一种边界情况：教程的 kernel 如果接收的是行步长为 16 的倍数、N 却不是的视图，编译器仍会成组地搬，会有一组跨过 N。这一组读到的仍是同一行里第 N 列之后的元素，没有越出这一行，结果又在写回时被丢掉，所以还是靠第 3 条兜住。

用法速查

写法与参数

offs = tl.max_contiguous(tl.multiple_of(offs, BLOCK), BLOCK)  # 一维：写一个数
ptrs = tl.multiple_of(ptrs, [1, 16])                           # 二维：每维一个，1 表示不声明

参数必须是编译期整数（constexpr），取 2 的幂。整数下标的整除度按元素算；指针的整除度按字节算，tl.multiple_of(ptr, 16) 的意思是 16 字节对齐。

精确含义

  • tl.max_contiguous(x, C)：x 能切成每 C 个一组、组内一路加一的段。
  • tl.multiple_of(x, D)：每组第一个元素是 D 的倍数。文档写的是“都是倍数”，那只在取值连续度为 1 时准确，比如标量和指针。
  • tl.max_constancy(x, C)：每 C 个一组、组内全部相等。

贴在哪里

  • 声明不做计算，只给定义这个值的那条操作挂上 tt.contiguity 或 tt.divisibility，再原样返回这个值。
  • 写在哪一行都一样，标签总回到值诞生的地方。值经过 if 或循环的合并点，信息取两边的最大公约数，标签随之丢失。R-03 就是这种情形。
  • 冷知识：代码生成器会先把循环体预演一遍，找出跨轮传递的变量。写在循环里、作用于循环携带变量的声明，因此落到了循环前那个值上，并且生效。这是实现细节，不要依赖。

教程里的三种用法

  • 09 第 135–136、320–321 行：tl.where 之后补回取值连续和对齐。
  • 06 第 59、70 行：标量，lo = tl.multiple_of(lo, BLOCK_M)，说明运行时算出的循环起点是块的倍数。
  • 08 第 148–149 行：从表里读出的指针，编译器不知道是否对齐，只能由人来声明。这两行在 K 循环里、返回值也没接，能起作用靠的正是上面那条冷知识。

编译器不检查声明。它用声明值直接替换自己推出的值。声明不成立、而那些数据又真的被用到时，会读错数据；地址实际不对齐时，运行时会报 misaligned address。原则：只在每个会被用到的组上都成立时才声明；像边界 tile 那样只在用不到的组里不成立时，要能说清它为什么不出事。

整数参数也带着一点编译期信息

每次发射，Triton 会看一眼实参，把下面几条信息固化进编译结果，同时写进缓存键：

实参固化进编译结果的IR 里的样子
整数恰好等于 1整个值，当作编译期常量参数直接变成常量 1
整数是 16 的倍数只有“是 16 的倍数”这一条，具体值仍在运行时传入%N: i32 {tt.divisibility = 16 : i32}
指针 16 字节对齐“16 字节对齐”这一条%b_ptr: !tt.ptr<f16> {tt.divisibility = 16 : i32}

所以 N = 208 和 N = 1024 共用一份编译结果，N = 200 会另编一份，那一份不知道行首对齐。用 @triton.jit(do_not_specialize=[...], do_not_specialize_on_alignment=[...]) 可以关掉这种特化。tl.constexpr 则把整个值固化进去，值一变就重新编译，比如练习里的 NUM_SMS：M1 里逐 tile（4096）和持久（170）各编译了一份。这也是验收项 A4 写明“N、K 整块且输入对齐时”、测试特意用 256 × 256 × 128 这样形状的原因。
