Grouped GEMM 数据搬运

矩阵乘指令不能直接对显存里的数据做运算。每一轮 K 循环开始前，A 的一块和 B 的一块要先从显存搬进 SM 上的共享内存。教程的两个 kernel 展示了三种搬法，区别在于谁来发指令、谁来算地址、搬的时候能不能同时计算。

一句话：编译器知道的越多，搬得越快。不知道对齐，只能每次搬 2 个字节；得到对齐承诺，每次搬 16 个字节，并且边搬边算；拿到描述符，整块交给硬件，连地址都不用线程自己算。

本页所有指令和数字都来自 2026-10-06 在本机对教程 kernel 的只编译结果（Triton 3.7.1，目标 sm_89 与 sm_90），没有在 GPU 上运行。sm_89 是 RTX 4070 Ti 这一代，sm_90 是带 TMA 的 Hopper。

先补四个概念

用 C/C++ 里的东西来对照

1显存与共享内存

显存（global memory）是整块 GPU 共用的大仓库，容量大，离计算单元远。共享内存（shared memory）是每个 CTA 在 SM 上的一小块工作台，离计算单元近，容量很小：本课的 kernel 每个 CTA 用 16 到 131 KB。这两个 kernel 里，矩阵乘用到的数据都要先放到工作台上。

对照 C：显存像 malloc 出来的大数组，共享内存像函数里的一个小局部数组。先 memcpy 一小块到局部数组，再在上面做密集运算。

2对齐与承诺

地址是 16 的倍数，叫 16 字节对齐。一次搬 16 个字节的指令要求地址对齐，否则行为未定义。编译器不确定时只能用最保守的搬法。

// 要求 p 是 16 的倍数，否则崩溃
__m128 v = _mm_load_ps(p);
// 向编译器保证 p 对齐，保证不成立就是未定义行为
float *q = __builtin_assume_aligned(p, 16);

tl.multiple_of(ptrs, [16, 16]) 就是 Triton 里的 __builtin_assume_aligned：它不检查，也不修正，只是一句保证。

3异步拷贝与流水

同步的做法是搬完一块、算完一块，再搬下一块，搬的时候计算单元闲着。异步拷贝只负责发起搬运，然后立刻返回；等第 2 块在路上的时候，可以先算第 1 块。流水有几级由 num_stages 决定。

对照 C：一个线程提前读下一个缓冲区，另一个线程处理当前缓冲区，也就是双缓冲。

4描述符

描述符是一张说明书：这片内存是几维的、每维多长、每维的步长是多少、一次搬多大一块。有了它，算地址这件事就从代码变成了数据，可以交给硬件去做。

struct TensorMap {      // 示意，真实对象是 1024 位
  void *base;           // 矩阵首地址
  int   dim[2];         // 行数、列数
  long  stride[2];      // 行步长、列步长（字节）
  int   box[2];         // 一次搬的块：行数、列数
  int   fill_mode;      // 越界部分填什么
};

对照 C：把这个结构体交给一个专门做 memcpy 的硬件，告诉它“从第 (i, j) 个元素开始搬一块”。

速查表

    
各种输入情形下，调用前要做什么

    
按“输入是什么样”来查。每一格写的是调用前要做的事，以及做与不做的后果。左列是教程的指针版，靠 tl.multiple_of 的保证用上异步拷贝；右列是描述符版。

  

  

    
三条原则

    
    
      
  1. kernel 和描述符都不会改动内存里的布局，所有要求必须在调用前就成立。
    2. 
      
  2. 输入的布局要改，只能拷贝一遍；输出只需要在分配时留好。
    3. 
      
  3. 指针版靠的是保证，没人检查；描述符版在 TMA 上是硬性要求。两者不满足时的行为都没有保证。
    4. 
    

  


  
一、对齐

  
“行步长”指相邻两行相隔的字节数。fp16 时，16 字节的倍数相当于 8 个元素的倍数。

  

    

      
输入的情形指针版加异步拷贝描述符版

      
        
首地址和行步长都是 16 的倍数不用处理。保证 16，每条指令搬 16 字节，有流水不用处理，可以直接用

        
行步长只是 8 或 4 的倍数不用拷贝。把保证改成 8 或 4，指令数变成 2 倍或 4 倍，仍有流水输入必须先拷贝到行步长为 16 倍数的缓冲区

        
行步长连 4 的倍数都不是不写保证，退回每次 2 字节的读，没有流水；或者拷贝补齐后保证 16同上，必须拷贝

        
首地址不对齐，例如 big[:, 4:]保证 16 不成立。按实际情况降档，或者拷贝必须拷贝

        
输出 C教程没有对 C 作保证，怎么分配都行分配时把行步长留宽到 16 的倍数，再切片，不需要拷贝

      
    

  


  
二、尺寸不是块的整数倍

  

    

      
输入的情形指针版描述符版

      
        
只有 M 不整数据不用处理。kernel 里给读 A 和写 C 加行方向的 mask，异步拷贝保持不变不用处理，界外的读补 0，界外的写被跳过

        
N 或 K 不整，选择一数据不用处理。三个方向都加 mask，代价是退回每次 2 字节的读，没有流水不用处理，同上

        
N 或 K 不整，选择二调用前把 A、B 补零到整块，C 按整块分配后切片。要拷贝一次输入，换来保持异步拷贝不需要这样做

        
完全不处理，也没有 maskM：写坏 C 之后的内存；N：C 内部出现竞争写；K：全部结果都可能出错不存在这个问题

      
    

  

  
描述符版虽然不怕尺寸不整，但第一张表的对齐要求照旧。比如输出维是 500 时，C 的行步长是 1000 字节，不满足要求。


  
三、存放方向与连续性

  

    

      
输入的情形指针版描述符版

      
        
行内不连续，例如 x[:, ::2] 或转置视图必须先 .contiguous()，kernel 假定行内步长是 1必须先 .contiguous()，描述符要求最后一维连续

        
B 按 [K, N] 存放直接用需要 B.T.contiguous()，一次转置拷贝

        
B 按 [N, K] 存放，即 PyTorch 线性层权重的习惯需要转置拷贝成 [K, N]直接用。kernel 里的 b.T 不搬数据，只是告诉矩阵乘指令第二个操作数是转置摆放的

        
dtype 不是 fp16教程把类型写死成 fp16，要先转换，或者改 kernel教程支持 fp16 和 FP8 两种

      
    

  

  
转置视图和转置拷贝的区别：B.T 不动内存，只是换一种读法，行内不再连续；B.T.contiguous() 才新开一块内存，按新的行优先顺序把数据拷进去。3 行 2 列的 B 在内存里是 0 1 2 3 4 5，转置拷贝之后是 0 2 4 1 3 5。


  
四、设备

  

    

      
设备指针版描述符版

      
        
sm_90 及以上异步拷贝，无额外准备TMA 整块搬运。发射前必须 triton.set_allocator，每个 CTA 要 768 字节的全局暂存区

        
sm_89 等没有 TMA 的设备异步拷贝照常可用描述符被改写成指针加 mask。结果正确，但没有异步拷贝

        
其他后端，例如 AMD能编译，搬运方式由后端决定同样被改写成指针加 mask

      
    

  


  

    
放到真实的 MoE 层里看

    
    
      
  1. 权重是静态的。按 [N, K]、行步长为 16 字节的倍数存一次，两个版本都能直接用。
    2. 
      
  2. 激活每次调用都在变，拷贝代价最高。好在隐藏维通常是 8 的倍数，也是块的整数倍，对齐和 N、K 的整块要求天然满足。
    3. 
      
  3. 真正每次都不同的只有行数。指针版用行方向的 mask，描述符版什么都不用做。
    4. 
      
  4. 输出在分配时留宽即可，没有拷贝。PyTorch 的 grouped_mm 就是这样处理它自己分配的输出的；对输入它只检查、不补齐，不满足就报错。
    5. 
    

  

  
依据：保证降到 8、4 字节时的搬法，mask 对流水的影响，描述符在 sm_89 和 AMD 上的改写，来自 2026-10-06 至 10-07 在本机的只编译结果。grouped_mm 的行为来自 PyTorch v2.13.0 的源码和 CPU 上的运行。都没有在 GPU 上实测。






  

    
小结

    
    
      
  1. 指针从地址表里读出来，编译器不知道它是否对齐。没有保证时，每个线程一次只搬 2 个字节，也做不了流水。
    2. 
      
  2. tl.multiple_of 是一句保证：有了它，每次搬 16 个字节，K 循环变成 3 级流水。保证不成立时行为未定义，没有人替你检查。
    3. 
      
  3. 描述符把“怎么算地址”交给硬件。一个线程发一条指令搬一整块，越界补 0，所以不需要 mask。
    4. 
      
  4. 描述符对象必须放在全局内存里。在设备上现场创建时，每个 CTA 要一小块全局暂存区，这就是 triton.set_allocator 的用处。
    5. 
      
  5. 没有 TMA 的设备上，描述符退化成指针加 mask：结果一样，搬法最普通。
    6. 
    

  






  

    
自测

    
先想，再展开看答案

  

  

    

      
1把指针版 kernel 里的两句 tl.multiple_of 删掉，结果还对吗？哪里会变？

      
看答案
        
结果仍然正确，因为这句话不改变计算。变的是搬运方式：每个线程每轮从 8 条 16 字节的异步拷贝，退回到 64 条 2 字节的读加 64 条写，K 循环也不再做流水。

      

    

    

      
2一个 fp16 矩阵每行 100 个元素，保留 tl.multiple_of 去跑指针版，会怎样？

      
看答案
        
每行 200 字节，除以 16 余 8。偶数行的起始地址对齐，奇数行不对齐，保证不成立。编译器照样生成一次搬 16 字节的指令，在不对齐的地址上执行属于未定义行为。把上面实验里的每行元素数改成 100 可以看到这一点。

      

    

    

      
3教程没有给 c_ptrs 写保证。写回 C 的那一步会受什么影响？

      
看答案
        
写回用的是逐个元素的写：每个线程 128 条，每条 2 个字节。我单独编译了一个只做写回的小 kernel 来验证：给 c_ptrs 加上同样的保证后，变成 16 条，每条 16 个字节。
