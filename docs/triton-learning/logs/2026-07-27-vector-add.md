## 学习过程

- [高价值问题] “对于tl.load中设置了mask，false的位置是变成了未定义，而不是变成空的消失是吗？”——我用最后一块 `[T,T,F,F]` 主动核对 `[9,10,未定义,未定义]` 与 `[9,10]` 的区别。
  答疑由此区分了控制访存和压缩形状，并追踪到无效值为什么仍可能污染 reduction；稳定解释见
  Lesson 01 的 Q01。（来源：[01-A · 005→007](../dialogues/01-vector-add.md)，2026-07-20
  02:24:41.115–02:26:03.340）
- [高价值问题] “那类似的，在tl.store函数的里的mask也会有类似的效果吗？”——这个追问把
  load 的返回值语义与 store 的写入副作用分开：false store lane 不写入，合法目标地址保持原值；
  它也不能修复此前已被污染的 reduction。稳定对照见 Lesson 01 的 Q02。（来源：
  [01-A · 008→010](../dialogues/01-vector-add.md)，2026-07-20 02:31:06.781–02:32:00.382）
- [高价值问题] “作为编译期参数的BLOCK_SIZE，必须以常量输入吗？还是也可以变化？”——问题
  澄清后，我接受了“在一次 kernel 特化中固定”和“不同 launch 可以选择不同 Python 整数”的
  区别，而没有把 `constexpr` 理解成源码里永远写死。稳定解释见 Lesson 01 的 Q03。（来源：
  [01-A · 011→014](../dialogues/01-vector-add.md)，2026-07-20 03:06:55.655–03:23:07.130）
- [高价值问题] “我不知道如何在参数中携带expected_exception。”——这次把异常类型也作为
  pytest 的参数数据，再由 `pytest.raises(expected_exception)` 检查拒绝行为；需要传异常类，
  不能把异常实例当成同一接口。参数化示例保存在 Lesson 01 的 Q05。（来源：
  [01-B · 007→010](../dialogues/01-vector-add-part2.md)，2026-07-22 08:02:31.946–08:04:01.367）
- [高价值问题] “什么情况下我们需要写成callable grid呢？”——追问把判断条件从“输入大小会
  变化”收紧到“grid 是否依赖 Triton 随后绑定的 meta-parameters”；本次 wrapper 已经确定
  block size，tuple grid 即可。稳定解释及 autotune 的例外见 Lesson 01 的 Q08。（来源：
  [01-B · 011→014](../dialogues/01-vector-add-part2.md)，2026-07-22 08:27:33.296–08:29:26.725）
- [纠错] 场景：解释 masked load 为什么保持形状。我说“数据目的地已经开辟好了与数据源大小一样
  的空间，所以返回形状与数据源固定一样”，后来又说“根据输入tensor的形状决定的”→ 正确：形状
  来自当前 program 的局部 pointer tensor，例如 `x_ptr + offsets`，不来自 wrapper 的输出分配，
  也不等于整个 PyTorch 输入的 shape。原因：`offsets` 等块级表达式确定了静态逻辑形状，mask 只
  控制各 lane 的访存和值。我最终明确复述“是局部的pointer tensor形状决定的，不是整个输入形状”。（来源：[01-B · 029→035](../dialogues/01-vector-add-part2.md)，2026-07-22
  09:32:50.778–09:54:01.913）
- [纠错] 场景：用填充值解释条件写回的越界安全。我说“如果写的mask没有考虑边界，就必须要让other=-inf了”→ 正确：应显式使用 `boundary_mask & condition`；不能把越界安全寄托于某个
  sentinel 恰好不满足当前条件。原因：比较条件或阈值改变后，填充值可能通过条件，而边界谓词
  始终负责排除非法地址。（来源：[01-B · 032→034](../dialogues/01-vector-add-part2.md)，
  2026-07-22 09:49:23.707–09:50:17.131）
- [转折] 我起初追问“抽象层”具体指什么，随后能区分 program instance、`arange` 构成的逻辑
  block tensor，以及实际 GPU threads/warps。这个分层把“`BLOCK_SIZE=4` 处理四个逻辑位置”与
  “硬件启动四个线程”分开，避免了直接套用 CUDA 标量线程模型。（来源：
  [01-B · 029→034](../dialogues/01-vector-add-part2.md)，2026-07-22 09:32:50.778–09:50:17.131）
- [转折] 从“如何构建非连续输入”的问题推进到复述地址契约：我指出现有 AXPBY 只做 `ptr+offset`
  地址计算，并提出若要支持非连续一维 tensor，需要增加 stride 参数及 `ptr+offset*stride`。
  这把 wrapper 的连续性限制与 kernel 实际访存方式联系起来；本段没有据此扩大实现范围。
  （来源：[01-B · 007→010、029](../dialogues/01-vector-add-part2.md)，2026-07-22
  08:02:31.946–09:32:50.778）
- [高价值问题] “triton.testing.Benchmark中的x_names可以设多个自变量吗？我这里需要size和block_size都变化。”——本次 Triton 3.7.1 的最小调用验证区分了成组横轴参数与不同曲线：多个 `x_names`
  不会自行生成参数笛卡尔积，当前实验用 `size` 作横轴、`block_size` 作 `line_arg`。API 细节
  与验证记录见 Lesson 01 的 Q10/Q11。（来源：[01-C · 010→016](../dialogues/01-vector-add-part3.md)，
  2026-07-23 08:07:07.815–08:13:09.912）
- [转折] 我追问尾块实验“为什么实验中有时会出现 GB/s 上升”，起初尝试从 GPU 优化解释。
  后续复盘转而使用 `tail_gbps/exact_gbps = (N_tail/N_exact) × (t_exact/t_tail)`：有效字节分子
  略增、独立测量的耗时相同或落入较低档位，都能让比值上升，不能据此断言物理 DRAM 带宽提升。
  最终 Review 确认报告已经补上这个因果区分，数值及实验边界保留在 AXPBY Benchmark 简报。
  （来源：[01-C · 046→048、069→073](../dialogues/01-vector-add-part3.md)，2026-07-24
  06:51:49.837–08:31:33.401）
- [高价值问题] “有没有办法在 benchmark 中让他跑多次取总时间啊？”——本次对照先澄清
  `do_bench(rep=100)` 是总采样预算，不会把一次 kernel 的计时间隔延长到 100 ms；批量后除以
  次数可以延长测量窗口，但缓存状态和发射方式也会改变，不能作为原单次结果的直接替代。
  对照口径见 Lesson 01 的 Q16。（来源：[01-C · 049→053](../dialogues/01-vector-add-part3.md)，
  2026-07-24 06:55:41.204–06:58:31.917）
- [转折] 我追问“约 1.024µs 的整数倍”从何而来。答疑从 p50 表格继续检查原始样本，才将它
  限定为当时 A100、驱动和 CUDA Event 测量路径中观察到的量化步长；没有把它解释成 GPU 只能
  按此步长执行，也没有当成所有 CUDA 环境的固定定律。观察与来源边界见 Lesson 01 的 Q17。
  （来源：[01-C · 054→058](../dialogues/01-vector-add-part3.md)，2026-07-24
  07:04:53.555–07:21:53.277）
- [转折] 复盘仍将 masked lane 不访存归因为可能的 GPU 优化时，我追问“既然不是gpu优化了冗余访存，那是为什么这部分访存动作没了？”对照当前 kernel 的 `@%p1 ld.global` / `st.global`
  后，模型改为：false predicate 对应地址的访存原本就不执行；这与 active lane 的物理事务
  粒度、仍可能存在的地址计算和调度成本是不同层次。最后一次定向 Review 确认该差值已写清。
  （来源：[01-C · 061→065、069→073](../dialogues/01-vector-add-part3.md)，2026-07-24
  07:28:02.398–08:31:33.401）
- [转折] 实验复盘的第一轮 Review 指出，原定 5% 反证条件已经被数据触发，不能因为后来发现
  阈值低于一个计时台阶就改称预测得到支持。后续记录分别保留“按原标准判定结果”和“改进下一次
  测量方法”，并把各 block size 的观测与可推广结论分开；最终复审确认该处修订通过。
  （来源：[01-C · 060→061、068→073](../dialogues/01-vector-add-part3.md)，2026-07-24
