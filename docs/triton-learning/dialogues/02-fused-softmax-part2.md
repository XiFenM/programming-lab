**015 · 助手 / 正式回答** · `2026-08-03T09:40:20.332Z`

### 为什么还要检查每行之和

Softmax 的定义直接保证：

\[
\sum_j \operatorname{softmax}(x)_j = 1
\]

因此，测试需要两种互补证据：

- 与 `torch.softmax` 逐元素比较：验证每个输出值。
- 检查每行之和接近 1：验证归一化这一核心数学不变量。

从逻辑上说，正确的逐元素对比已经隐含了行和正确；但独立断言能让失败原因更清楚。如果 row sum 失败，通常应该优先检查 `tl.sum`、分母或除法，而不是索引和输出布局。它也能防止 reference 不小心使用错误维度时两边一起比较错。

测试结构可以是：

```python
if size_m > 0:
    expected_row_sums = torch.ones(
        size_m,
        device=actual.device,
        dtype=actual.dtype,
    )
    torch.testing.assert_close(
        actual.sum(dim=1),
        expected_row_sums,
        rtol=RTOL,
        atol=ATOL,
    )
```

只要求非空正确用例，是因为 `M=0` 时没有任何行需要验证。

### 第三项设计说明是什么

它指提交问题中的第 3 题：

> 为什么 `M=0` 可以直接返回，而 `N=0` 应由本练习的接口拒绝？

区别是：

```text
M=0, N>0：
没有任何样本/行，但每行应有的列维度是合法的。
没有 row 需要计算，可以明确返回 shape=(0, N) 的空结果。

M>0, N=0：
存在 M 个样本，但每个样本的 softmax 计算域为空。
没有有效元素可求 row max，空行的元素和也无法归一化成 1。
```

从 kernel 角度看，`N=0` 还会造成：

```text
所有 lane 都无效
row max 只能来自 -inf padding
-inf - (-inf) 产生 NaN
```

所以本练习选择在 wrapper 中明确拒绝 `N=0`。主要原因是空 reduction domain 不符合 softmax 和本 kernel 的语义前提；是否浪费一次 kernel launch 只是次要后果。

这是本练习定义的严格接口契约，不代表所有框架必须采用相同选择。相关提示已记录在 [P01-R03/R04](/workspace/docs/triton-learning/lessons/02-fused-softmax.md:1172)。
