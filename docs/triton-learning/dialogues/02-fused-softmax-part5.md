**004 · 助手 / 正式回答** · `2026-08-07T01:28:49.518Z`

核心区别是：两者前半段几乎完全相同，但最后输出的表示不同。Log-softmax 不能简单实现成 `log(softmax(x))`，必须直接使用稳定的 log-sum-exp 公式。

### 1. 数学与输出区别

对一行输入 \(x\)，先计算：

\[
m=\max(x),\qquad z_i=x_i-m,\qquad s=\sum_j e^{z_j}
\]

| 算子 | 稳定公式 | 输出含义 | 每行不变量 |
| --- | --- | --- | --- |
| softmax | \(e^{z_i}/s\) | 概率 | \(\sum_i y_i \approx 1\) |
| log-softmax | \(z_i-\log(s)\) | 对数概率 | \(\operatorname{logsumexp}(y)\approx0\) |

因此：

\[
\operatorname{logsoftmax}(x)_i
=x_i-\operatorname{logsumexp}(x)
=z_i-\log(s)
\]

Log-softmax 的输出通常小于等于 0；但它的一行之和没有固定意义，不能像 softmax 那样检查“每行和接近 1”。可以检查：

```python
torch.logsumexp(output, dim=1)  # 应接近 0
```

或者：

```python
output.exp().sum(dim=1)  # 应接近 1
```

`N=1` 时，唯一类别的概率是 1，所以 log-softmax 输出是 `log(1)=0`。

### 2. 为什么不能先 softmax 再 log

考虑 float32 输入：

```text
x = [0, -1000]
```

实际最小验证结果是：

```text
softmax(x)      = [1, 0]
log(softmax(x)) = [0, -inf]
log_softmax(x)  = [0, -1000]
```

第二个概率太小，softmax 会先把它下溢成精确的 0，之后 `log(0)` 就只能得到 `-inf`。

而稳定 log-softmax 不需要把最终概率真正表示出来：

```text
z = [0, -1000]
s = exp(0) + exp(-1000) ≈ 1
output = z - log(s) ≈ [0, -1000]
```

所以 log-softmax 保留了极小概率对应的有限对数值。这也是分类任务通常使用 log-softmax/NLL，而不是手动写 `log(softmax(x))` 的重要原因。

### 3. 对现有 Triton kernel 的修改位置

普通 softmax 的主体位于 [lesson02_fused_softmax.py](/workspace/gpu/triton/lesson02_fused_softmax.py:79)：

```python
data = tl.load(..., other=-float("inf"))
max_data = tl.max(data)
exp_data = tl.exp(data - max_data)
sum_exp_data = tl.sum(exp_data)
exp_data = exp_data / sum_exp_data
tl.store(..., exp_data, ...)
```

Log-softmax 的稳定写法会变成：

```python
data = tl.load(..., other=-float("inf"))
max_data = tl.max(data)
row_minus_max = data - max_data
exp_data = tl.exp(row_minus_max)
sum_exp_data = tl.sum(exp_data)
log_probs = row_minus_max - tl.log(sum_exp_data)
tl.store(..., log_probs, ...)
```

也就是：

- 第 79–80 行的 masked load 和 max reduction 不变。
- 第 81–82 行仍然需要 `exp` 和 sum reduction。
- 第 83 行由“向量除以行和”改为“向量减去行和的 log”。
- 第 84 行存储 log probabilities。

Persistent 版本只需相应修改[循环体第 96–101 行](/workspace/gpu/triton/lesson02_fused_softmax.py:96)。以下部分都不需要改变：

- program 与行之间的 grid-stride 映射；
- `BLOCK_SIZE` 和 power-of-two padding；
- load/store mask；
- persistent grid 的基本推导方式；
- `num_stages` 所描述的跨行循环软件流水。

一个容易产生的误解是：log-softmax 并没有消除 `exp`。它仍然要通过：

\[
\log\left(\sum_i e^{x_i-m}\right)
\]

计算归一化项，只是不把 `exp(z_i)` 当作最终输出。

### 4. Padding 与空维度

`other=-inf` 对 log-softmax 仍然正确：

- max reduction 时，padding 不会成为最大值；
- `exp(-inf)=0`，所以不影响指数和；
- 最终 padding lane 得到 `-inf`，但会被 store mask 排除。

对于至少包含一个有限值的非空行，最大元素对应：

\[
e^{m-m}=e^0=1
\]

所以指数和至少为 1，`log(s)` 有定义。

这也进一步解释了之前的接口选择：

- `M=0`：没有样本，直接返回空输出即可。
- `N=0`：没有有效元素，无法求 max，也没有 `exp(0)=1` 这个锚点，应由 wrapper 拒绝。

还应留意非有限输入：全是 `-inf`，或者含有 `+inf` 时，`inf-inf`、`-inf-(-inf)` 都可能产生 NaN。是否接受这种传播行为，应由接口契约明确；当前练习没有额外拒绝非有限值。

### 5. 性能与资源不一定完全相同

两者逻辑上的全局内存流量仍然都是每个元素一读一写，但指令和变量生命周期不同：

- softmax：保留 `exp_data`，最后做向量除法；
- log-softmax：需要保留 `row_minus_max`，指数和完成后再做一次每行 `log` 和向量减法。

这可能改变寄存器 live range、register 数量、shared memory、resident programs 和最合适的 `num_stages`。因此如果使用资源推导 persistent grid，必须针对编译后的 log-softmax specialization 重新读取资源，不能直接复用 softmax 的资源记录。

### 6. 如果用于训练

Log-softmax 常和 NLL loss 配合。目标类别为 \(k\) 时：

\[
\text{cross-entropy}(x,k)
=-\operatorname{logsoftmax}(x)_k
\]

不过当前 Triton wrapper 只是 forward 教学算子。即使 forward 数值正确，也不能直接替换训练中的 PyTorch 算子；还需要 backward/autograd 集成。Log-softmax 的反向公式为：

\[
\nabla x_i
=g_i-\operatorname{softmax}(x)_i\sum_j g_j
\]

最简洁的心智模型是：

> softmax 是“稳定指数化后归一化”；log-softmax 是“输入减去稳定计算的 log-sum-exp”。前者输出概率，后者直接输出对数概率。

**007 · 助手 / 正式回答** · `2026-08-07T01:38:59.977Z`

是的，你的理解正确。

两者可以复用相同的 Triton 整体框架：

- 一行由一个 program 处理
- `BLOCK_SIZE` 补齐到 2 的幂
- masked load/store 与 `-inf` padding
- max、sum 两次 reduction
- kernel fusion
- persistent grid-stride 调度
- `num_warps`、`num_stages` 等优化方法

核心计算仅从：

```python
softmax = exp(row_minus_max) / sum_exp
```

变成：

```python
log_softmax = row_minus_max - tl.log(sum_exp)
```

但有三点不能直接照搬：

1. 必须直接实现稳定公式，不能写 `tl.log(softmax)`。
2. 正确性不变量变成每行 `logsumexp(output) ≈ 0`，而不是输出之和接近 1。
3. 指令和变量生命周期发生变化，编译后的 registers、shared memory、occupancy 和最佳 `num_stages` 可能不同，因此仍需针对新 kernel 重新测量，不能直接复用 softmax 的资源/grid 结果。
