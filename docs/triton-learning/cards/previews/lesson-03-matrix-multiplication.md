## 01. 计算 C=A×B，其中 A 的形状为 \[M,K\]、B 为 \[K,N\]。若一个 program 负责 C 的一个 \[BLOCK\_M,BLOCK\_N\] 输出块，它如何沿 K 轴完成这个块的计算？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：固定输出块覆盖的 M 行和 N 列，沿共享的 K 轴逐段加载 A、B，并把每段矩阵乘法的结果累加到同一输出块。

- **初始化**：为这块输出建立形状为 \[BLOCK\_M,BLOCK\_N\] 的 accumulator，并初始化为零。它的两个轴对应输出行和输出列，不包含 K 轴。
- **每轮加载**：在当前 K 段，加载 A 的 \[BLOCK\_M,BLOCK\_K\] 块以及 B 的 \[BLOCK\_K,BLOCK\_N\] 块；两者共享同一段 K 坐标。
- **乘加与推进**：两块相乘得到 \[BLOCK\_M,BLOCK\_N\] 的部分和并加入 accumulator，然后把 A 的列基址和 B 的行基址各推进 BLOCK\_K；输出行列坐标保持不变。
- **完成输出**：遍历全部 K 段后，accumulator 才包含完整点积，可以写回该 program 负责的 C 块。

**边界**：K 尾部不足整块时，越界输入应补零，避免污染点积；M/N 尾部的无效输出不写回。FP16 输入配 FP32 累加是一种精度选择，并不是上述分块数据流的数学前提。

### 锚点

固定 M/N，遍历 K，累加部分和

## 02. 在 Triton 分块矩阵乘法中，offs\_k=tl.arange(0,BLOCK\_K) 表示块内 K 偏移。若 K 循环通过移动 A/B 指针基址推进，offs\_k 本身会怎样变化？

类型：技术问答 · 层级：原子 · 等级：A

适用范围：triton · 3.7.1

### 答案

**结论**：offs\_k 本身保持不变；每轮变化的是 A/B 指针基址，因此同一组局部偏移会指向不同的全局 K 坐标。

- **通用关系**：将循环轮次记作 t，从 0 开始计数，则该轮全局 K 坐标为 t×BLOCK\_K+offs\_k；局部 offsets 始终是 0 到 BLOCK\_K−1。
- **具体例子**：BLOCK\_K=4 时，第二轮 t=1：offs\_k 仍为 \[0,1,2,3\]，指针指向的全局 K 坐标则为 \[4,5,6,7\]。

**边界**：如果总长度 K=5，第二轮只有全局坐标 4 有效，5、6、7 必须在 load 时屏蔽并补零。这里讨论的是移动指针基址的循环写法，不能把局部偏移和全局坐标混称为同一个量。

### 锚点

局部偏移不变，K 基址推进

## 03. 计算 C\[M,N\]=A\[M,K\]×B\[K,N\] 时，若 K 不是 BLOCK\_K 的整数倍，为什么不能只靠最终写回 C 的 mask 来处理 K 尾部的越界读取？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：因为 K 是每个有效输出元素内部的求和轴；错误的尾部输入会先进入有效结果的累加和，写回 mask 无法再把这些错误项剔除。

$$
C_{ij}=\sum_{k=0}^{K-1}A_{ik}B_{kj}
$$

- **污染发生的位置**：对合法的 i、j，如果最后一块仍把 k≥K 的数据参与乘加，得到的 accumulator 就已经不是上式的结果。
- **写回 mask 的职责**：最终 mask 只判断输出行 i&lt;M、列 j&lt;N 是否有效。它能丢弃不存在的 C 元素，却不能检查一个合法 C 元素内部哪些乘积来自错误 K 坐标。

**边界**：因此 K 尾部必须在读取 A/B 时屏蔽并补零，使额外乘积为零；M/N 输出边界才由最终 store mask 裁掉。

### 锚点

归约前补零，写回时裁边界

## 04. 在分块矩阵乘法 C\[M,N\]=A\[M,K\]×B\[K,N\] 的边界块中，为什么可以让超出 M/N 的位置通过取模读取合法的替代输入，再丢弃对应输出？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：因为 M/N 决定的是不同输出元素的位置，而不是同一个输出内部的求和项；无效行列位置的计算只会生成最终被丢弃的输出。

- **替代输入的作用**：例如无效的 A 行号对 M 取模、无效的 B 列号对 N 取模，可以让读取落在合法地址，同时保留固定大小的输入 tile。这里的替代值只是为无效输出位置提供占位计算。
- **为何不污染有效结果**：矩阵乘法的每个 C\[i,j\] 只沿 K 求和，不会把别的输出行或列加进自己。有效 i、j 的点积仍使用其本来对应的 A 行和 B 列。
- **写回条件**：写回时必须用未经取模的原始输出行列号判断 i&lt;M 且 j&lt;N，丢弃替代位置算出的结果。

**边界**：M/N load 直接用 mask 也能保证正确，取模并不保证更快。这个理由不能用于 K：K 若回绕并参与求和，就会把重复乘积加进有效输出。

### 锚点

无效输出可丢弃，归约污染不可丢弃

## 05. 计算分块矩阵乘法覆盖 M 个输出行所需的 tile 数量。

类型：真实纠错 · 层级：原子 · 等级：B

### 场景

每个输出 tile 覆盖 BLOCK\_SIZE\_M 行；M 不能被块长整除，因此最后不足一块的行也必须有 program 处理。

### 正确

使用 cdiv(M, BLOCK\_SIZE\_M)，把原始总行数和每块行数作为两个参数传入。

### 错误

cdiv(M // BLOCK\_SIZE\_M)

### 说明

**结论**：向上整除的目标是把不足一块的剩余行也计为一块，不能先用整数除法丢掉余数。

- **通用含义**：所需块数为 ceil(M/BLOCK\_SIZE\_M)。cdiv 接收原始长度与块长，而不是接收已经算过的整数商。
- **具体例子**：M=257、BLOCK\_SIZE\_M=64 时，前四块只覆盖 256 行，还需要第五块处理最后一行。257//64 等于 4，已经丢失了这个尾部信息。

**边界**：长度和块长取正整数。若进一步计算分组数量，同理应写 cdiv(num\_pid\_m,GROUP\_SIZE\_M)，不能先整除。

## 06. Triton 矩阵乘法把输出划成 4 行、3 列的 tile 网格，并按 GROUP\_SIZE\_M=2 做 grouped PID 映射。第一组中，递增的 PID 怎样对应到输出 tile 坐标？

类型：技术问答 · 层级：原子 · 等级：A

适用范围：triton · 3.7.1

### 答案

**结论**：在同一组内，先遍历组内的 M 行，再切换到下一个 N 列；因此第一组依次处理 (0,0)、(1,0)、(0,1)、(1,1)、(0,2)、(1,2)。

- **坐标约定**：每个坐标写作 (输出 tile 行号,输出 tile 列号)，不是原矩阵中的单个元素坐标。这里第一组覆盖 tile 行 0、1，组高为 2。
- **映射规律**：把组内线性编号记作 p，实际组高记作 h，则组内行号为 p%h，输出 tile 列号为 p//h；全局行号还需加上该组起始 tile 行号。
- **复用关系**：pid=2 和 pid=3 分别负责 (0,1)、(1,1)：输出行不同、输出列相同，因此在相同 K 段需要同一个 B 列 tile。

**边界**：这里描述的是线性 PID 到输出坐标的映射，不是 GPU 执行完成顺序的保证。最后一组若不足两行，必须改用实际组高。

### 锚点

组内先 M，后 N

## 07. 分块矩阵乘法按 GROUP\_SIZE\_M 个输出 tile 行分组时，若最后一组不足整组，为什么 PID 映射必须使用尾组的实际行数？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：因为最后一组实际存在的行变少，组内 PID 对行号取模、对列号整除时也必须使用这个实际组高，否则会同时出现越界 tile 和遗漏 tile。

- **实际组高**：设 tile 总行数为 num\_pid\_m，当前组的起始 tile 行号为 first\_pid\_m，则实际组高是 min(GROUP\_SIZE\_M,num\_pid\_m−first\_pid\_m)。
- **具体例子**：tile 网格有 5 行、3 列，设定组高为 2。前两组覆盖行 0–3，尾组只有行 4，所以剩余 pid=12、13、14 应依次映射到 (4,0)、(4,1)、(4,2)。
- **错误后果**：若尾组仍按两行计算，pid=13 会被映射到不存在的 (5,0)，pid=14 只到 (4,1)，导致必须计算的 (4,2) 没有 program 负责。

**边界**：完整组继续使用设定组高；仅当剩余 tile 行数不足一组时缩小。实际组高保证的是输出覆盖正确性，不能仅靠 store mask 修复遗漏。

### 锚点

不越界，也不漏块

## 08. 在 Triton kernel 内求两个标量的较小值，以确定输出 tile 尾组的实际组高。

类型：真实纠错 · 层级：原子 · 等级：A

适用范围：triton · 3.7.1

### 场景

Triton 3.7.1 中，x 是设定的 GROUP\_SIZE\_M，y 是尚未覆盖的输出 tile 行数；此处需要在 x、y 两个数之间取最小值。

### 正确

使用 tl.minimum(x, y) 比较这两个值。

### 错误

tl.min(x, y)

### 说明

**结论**：tl.minimum 比较两个输入的对应元素；tl.min 则对一个输入沿指定轴做归约，两者承担的任务不同。

- **错误根因**：把 tl.min(x,y) 当成双参数取最小值时，y 会被解释为归约轴，而不是第二个待比较的标量，因此不符合尾组大小计算的需求。
- **回到任务**：例如设定组高 x=2、剩余行数 y=1，目标是得到实际组高 1；tl.minimum(x,y) 正好表达这个比较。

**边界**：这里绑定 Triton 3.7.1 的 API。需要沿张量的某个轴求最小值时，tl.min 仍然是相应的归约操作。

## 09. 为同一个矩阵乘法 A\[M,K\]×B\[K,N\] 选择 BLOCK\_M、BLOCK\_N、BLOCK\_K 时，为什么只比较输入 shape、program 数和 K 循环次数，仍不能确定哪组 tile 配置最快？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：因为 tile 大小同时改变数据复用、无效工作量和硬件资源占用；program 更少或循环更短，只减少了部分开销，并不等于总延迟更低。

- **边界工作量**：M/N 尾部不满时，大 tile 可能让更多输出位置参与计算却最终不写回；仅数 program 个数会忽略这些额外工作。
- **资源占用**：更大的输出 tile 需要更大的 accumulator，可能提高寄存器占用，使能够同时驻留的 program/warp 变少。这会改变隐藏访存或执行延迟的机会，不能只根据输出块更大就判断更快。
- **配置共同作用**：数据复用、warps/stages、GPU 架构和编译结果都会影响实际瓶颈；同样的 M/N/K 在不同配置和设备上可能得到不同胜负。

**边界**：shape 分析适合筛选候选和提出预测。最终判断应在目标 GPU 上、相同输入和可比计时条件下测量，不能仅用“M/N 大、K 小”宣布某组配置更快。

### 锚点

复用收益与资源代价共同决定性能

## 10. 比较同一矩阵乘法的两种 GROUP\_SIZE\_M 配置时，若多轮 benchmark 无法把配置造成的耗时差异与 GPU 运行状态漂移稳定区分，应该怎样表述性能结论？

类型：技术问答 · 层级：原子 · 等级：A

### 答案

**结论**：应表述为：在当前设备、输入形状、launch 配置和测量方法下，证据不足以稳定区分两种分组配置的性能。

- **为何证据不足**：运行状态随时间变化本身就会改变耗时；如果这种变化与配置间的差异混在一起，就不能把观测到的快慢可靠归因于 GROUP\_SIZE\_M。
- **不能推出什么**：既不能据此宣布某个配置更快，也不能说“真实影响很小”。看不清一个差异，可能是测量噪声太大，而不是差异本身很小。

**边界**：结论必须限定在已经测量的条件内；更换设备、shape 或测量方法后，需要重新验证，而不能把此次“分不出来”推广为普遍无收益。

### 锚点

分不出来，不等于差异很小

## 11. 分块矩阵乘法中，grouped ordering 通过重排线性 PID 到输出 tile 的映射，为什么可能提高 GPU 的 L2 cache 命中率并加速计算？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：它让需要相同 A/B 输入 tile 的 program 在映射上更接近，缩短数据再次被访问的间隔；如果数据此时仍在 L2 中，就可能减少重复从显存读取的流量。

- **复用机会**：同一输出 tile 列的不同行，会在相同 K 段使用同一个 B tile；同一输出 tile 行的不同列，也会使用相同 A tile。分组排序尝试让这些复用更及时。
- **缓存条件**：“访问间隔短”必须短到数据尚未被其他访问从 L2 淘汰，才可能转化为命中收益。较大的二维 tile 网格提供更多重排空间。
- **何时更有帮助**：当计算对访存较敏感，且 group size 与并发窗口、block 配置和目标架构匹配时，减少显存流量更有机会降低耗时。

**边界**：PID 映射不强制实际调度顺序；L2 容量和并发访问也会改变数据驻留。因此 grouped ordering 不能保证每次更快，更不能推出 group size 越大越快。

### 锚点

复用赶在 L2 淘汰之前

## 12. 请用 45–90 秒解释：分块矩阵乘法的 grouped ordering 如何争取 L2 复用收益；如果两种分组配置的 benchmark 差异与运行漂移混在一起，又应该如何报告结论？

类型：综合口述 · 层级：口述 · 等级：A

### 参考回答

**结论**：Grouped ordering 尝试改善输入 tile 的访问局部性，但是否加速必须由目标设备上的可区分测量支持。

- **复用机制**：重排 PID 到输出 tile 的映射，让需要相同 A/B tile 的 program 在映射上更接近。若重复访问发生在数据仍驻留 L2 的时间窗口内，就有机会减少显存读取。
- **生效条件**：二维 tile 网格要有足够重排空间，计算也要对访存足够敏感；分组大小、block 配置、并发窗口和架构都会影响复用是否兑现。
- **如何解释测量**：若多轮测试仍无法把配置影响与运行状态漂移稳定分离，应报告当前证据不足。不能宣布哪组更快，也不能进一步证明真实效应很小。

**边界**：这些判断仅适用于所测的设备、shape、launch 配置与计时口径；一次对照不能支持跨设备、跨形状或所有分组大小的性能结论。

### 评分锚点

说明 A/B tile 的复用机会来自哪些输出块；说明复用间隔必须落在 L2 驻留窗口内；说明设备、形状和分组配置的影响；把无法区分表述为证据不足，并限制外推范围
