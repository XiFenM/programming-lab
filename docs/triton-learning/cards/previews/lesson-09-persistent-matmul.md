## 01. 持久化矩阵乘里，tile 循环套着 K 循环，K 循环用 num_stages 做软件流水。在 tile 循环的 tl.range 上写 flatten=True 后，编译器做了什么？每个 CTA 省掉了什么、省不掉什么、代价是什么？

类型：技术问答 · 层级：机制 · 等级：A

适用范围：triton · 3.7.1

### 答案

**结论**：编译器把两层循环合成一层，软件流水于是能跨过 tile 的边界：下一个 tile 的读入在当前 tile 还没算完时就已发出。

- **省掉**：流水的预热与排空从每个 tile 一次变成每个 CTA 一次，tile 边界上等第一批数据的空档消失。
- **省不掉**：tile 自己的 prologue（算坐标）与 epilogue（写回）仍是每个 tile 一次，合并后它们变成循环体里的两个条件分支（scf.if）。
- **代价**：epilogue 执行时下一个 tile 的输入已在路上、输入缓冲仍被占着，写回用的中转缓冲不能再借用空出的输入槽，共享内存多一档。

**边界**：它是请求不是保证：只有 tile 循环里直接套一个 K 循环、中间没有别的 if 或 while、内层边界不随外层变化（或用 tl.assume 说明至少执行一次）时才合并；不满足时不报错，原样保留两层循环。

### 锚点

预热排空每 CTA 一次；prologue 与 epilogue 仍每 tile 一次；多一块中转

## 02. 持久化矩阵乘里 B 按行主序 \[K, N\] 存放（沿 N 连续），A 是 \[M, K\]（沿 K 连续）。N 方向的下标 offset_n 在 tile 开头算好并加了连续性声明，K 方向的 offset_k 在 K 循环里算。flatten 关时 A、B 都是 16 字节异步拷贝；flatten 开时只剩 A 是，B 退回同步读入。为什么？怎样修？

类型：技术问答 · 层级：机制 · 等级：A

适用范围：triton · 3.7.1

### 答案

**结论**：合并后 tile 开头的代码被包进一个 scf.if，offset_n 作为这个 if 的结果传出；流水挑选读入时看不到附在它上面的连续性声明，B 就不能成组搬。

- **为何丢**：进入新 tile 的那一轮走 if 分支、带着声明；其余各轮沿用上一次的值。合并点上两边的信息取最大公约数，声明随之丢失。
- **A 为何没事**：A 的连续方向是 K，offset_k 一直在每轮都执行的 K 循环体里计算，声明就在流水看得到的地方。
- **修法**：把 B 连续方向的下标（连同它的改写与声明）挪进 K 循环里，由 tile 坐标重新计算。

**边界**：只挪声明那一行没有用，声明贴在定义值的那条操作上；按 b.T 传入的 B 沿 K 连续，不受这个问题影响。

### 锚点

prologue 的值经 scf.if 传出会丢声明；连续方向的下标在 K 循环里算

## 03. 逐 tile 发射的矩阵乘，每个 tile 都要付一笔固定成本：CTA 发射、prologue、等第一批数据、epilogue。块较小、一个 SM 能同时驻留多个 CTA 时，常说这笔成本会被“掩盖”；块很大、一个 SM 只放得下一个 CTA 时就掩盖不了。掩盖是怎样发生的？为什么大块时不行？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：固定成本并没有消失，每个 CTA 照样付；掩盖的意思是张量核心不闲。空转要按 SM 算，而 SM 上的 warp 调度器在所有驻留的 warp 之间切换。

- **调度**：调度器每个周期从就绪的 warp 里挑一个发射，不区分它来自哪个 CTA；一个 CTA 在等数据或做 epilogue 时，别的 CTA 的 warp 接着用张量核心。
- **本质**：固定成本大多是等待（等发射、等数据），等待可以很多 CTA 同时进行；多驻留就是把串行的等待变成并行的等待。
- **大块**：一个 SM 只有一个 CTA 时，它等待的那段时间里没有别的 warp 可以顶上，就是张量核心的真空档。

**边界**：多驻留不增加张量核心的容量，收益上限是纯乘加的时间；大块时只能靠同一个 CTA 自己把等待和计算叠起来，也就是持久化加 flatten，或 warp 专用化。

### 锚点

空转按 SM 算；调度器只看 warp；等待可以并行

## 04. 为了让持久化矩阵乘在 tile 边界上不停下来，有两种办法：循环合并（flatten）和 warp 专用化。两者在机制上的根本区别是什么？各自的代价是什么？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：flatten 改的是一条执行顺序里的先后，像单线程的异步；专用化增加执行顺序的条数，像多线程的生产者与消费者。

- **flatten**：同一批 warp 仍按一条顺序执行，编译器把“发出下一个 tile 的读入”挪到当前 tile 最后几轮乘加之前，提前量固定为 num_stages − 1 轮。
- **专用化**：另分一批 warp 只做搬运，它的程序里两次读入之间没有乘加和 epilogue，只要有空槽就发，提前量由缓冲大小决定。
- **代价**：flatten 不加人手，只多一块中转缓冲，乘加与 epilogue 仍不能重叠；专用化要多发 warp（例如 8 个变 12 个），还要付屏障同步和更多缓冲（每个操作数从 S − 1 个槽变成 S 个）。

**边界**：两者不互斥，都依赖异步拷贝；区别只在由谁、在什么时候安排发出读入。

### 锚点

一条顺序里挪先后 vs 多一条顺序

## 05. 分块矩阵乘里，M、N、K 都可能不是块的整数倍。Triton 持久化矩阵乘教程对 M、N 方向的越界下标用 tl.where 改成 0，对 K 方向却用 mask 并让越界位置读成 0。为什么 M、N 可以“改成 0”，K 不行？M、N 方向为什么又非处理不可？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：M、N 是自由维度，越界的行列只影响 C 的越界部分，写回时丢掉即可；K 是被求和的维度，越界位置的值会进入每个输出的和，必须读成 0。

- **M、N**：下标改成 0 后读到的是第 0 行或第 0 列的真实数据，算出的结果落在越界的行列里，写回时被 mask 丢掉，只需保证地址合法。
- **K**：若把 K 方向下标也改成 0，越界位置读到的是第 0 列的 A 和第 0 行的 B，每个输出都多加几份 a\[m,0\]·b\[0,n\]。
- **为何要处理**：不处理时 tl.load 真的访问矩阵之外的地址，是未定义行为：可能读到别的分配而碰巧正确，也可能触发非法访问。

**边界**：数值测试发现不了 M、N 方向的越界读，只能在写法上保证；改下标、取模、给读入加 mask 都可以，区别在能否保住成组读入。

### 锚点

自由维度保地址合法；被求和维度保值为 0

## 06. Triton 编译器要知道下标张量的取值是否一路加一（取值连续度），才能决定能否成组读取。对 offs = pid_n * 64 + tl.arange(0, 64) 做 tl.where(offs < N, offs, 0) 之后，编译器认定它的取值连续度只剩 1，读入因此退回逐元素。为什么？这是不是说值真的不连续了？

类型：技术问答 · 层级：机制 · 等级：A

适用范围：triton · 3.7.1

### 答案

**结论**：对 where（IR 里的 select），结果的取值连续度取 x、y 的取值连续度和条件的恒定度三者的最大公约数；y 是常量 0，取值连续度为 1，结果也就只剩 1。

- **为什么取 gcd**：r\[i\] = cond\[i\] ? x\[i\] : y\[i\] 逐位置取值；编译时不知道 N，就不知道哪些位置取自 y，只能按对任何 N 都成立的方式记账：一组里混着取，或整组都取 y，都不连续。

**边界**：这是保守结论，不是值真的乱了；只用 mask、不改写下标时，下标的取值连续度仍是 64，不需要声明。

### 锚点

select 取 gcd；常量 0 的取值连续度是 1

## 07. 要用实测检验“持久化矩阵乘比逐 tile 发射快，而且优势随 K 增大而变小”。Triton 教程自带的 bench 让各 kernel 分别 autotune，持久版还同时带着 flatten，各版本先后连续跑。怎样设计测量，才能把速度差别归到某个具体改动上？

## 12. Triton 持久化矩阵乘教程的 TMA 版，把 B 按 \[N, K\] 存放（沿 K 连续），而不是普通 a @ b 的 \[K, N\]。为什么这样摆？fp16 和 fp8 在这件事上有什么不同？

## 13. 从 mma.sync（操作数和累加器都在寄存器里）到 wgmma（操作数直接读共享内存），再到 tcgen05（累加器放进 TMEM），新一代张量核心让数据离开了线程的寄存器，代价是共享内存占用变多。硬件为什么要这样做？只是给数据换个地方放吗？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：目的不是换地方，而是把通用线程从数据通路上拿掉：张量核心越来越不依赖线程去喂数据和存结果。

- **寄存器紧**：寄存器按线程私有且有上限，矩阵要切成碎片分给每个线程；128 × 128 的 fp32 累加器就占掉一个 SM 全部寄存器的四分之一，限制了块大小和驻留数。
- **逐条喂**：数据在寄存器里，线程就得一条条指令去取操作数、发乘加（sm_89 上每个 warp 每轮 24 条 ldmatrix 加 64 条 mma.sync）；后几代由张量核心成块地自己去取。
- **绑定**：数据在谁的寄存器里，计算就绑在谁身上：这批线程守着乘加，腾不出手做写回或搬运；数据搬走之后，乘加变成“发出去、稍后再等”。

**边界**：代价是输入槽被占得更久、写回要在共享内存里中转，所以共享内存上限较低的设备更受制约；三条原因各贡献多少性能没有实测。

### 锚点

寄存器私有有上限；线程逐条喂；计算绑在持有数据的线程上

## 14. Triton 持久化矩阵乘教程在 tl.where 把越界下标改成 0 之后，用 tl.max_contiguous 和 tl.multiple_of 声明下标“每 64 个一路加一”。可在跨过边界的那个 tile 里，例如 N = 208、第 3 号 tile 负责第 192–255 列，改写后是 192…207 再跟 48 个 0，声明并不成立。为什么这样写不会读错数，也不会越界？

类型：技术问答 · 层级：机制 · 等级：A

适用范围：triton · 3.7.1

### 答案

**结论**：声明只在用不到的组里不成立：编译器只在能证明对齐时才成组读，这时边界一定落在两组之间；不成立的那些组要么被 mask 掉不读，要么读到的值在写回时被丢弃。

- **对齐前提**：编译器只有证明了行首对齐才会成组地搬；N 是 16 的倍数时（发射时的特化让它知道这一点）才可能，否则直接逐元素读，声明用不上。
- **边界在组间**：每组 8 个元素，组首是 8 的倍数；N 是 16 的倍数也就是 8 的倍数，N 本身就是某一组的组首，不会出现半组有效、半组越界。
- **越界值无影响**：mask 用改写前的下标计算时，全是 0 的组整组被 mask 掉，拷贝的源字节数为 0、不读源地址；教程的 B 没有 N 方向的 mask，这些组会读到第 0–7 列，但只影响第 N 列以后的输出，写回时被丢弃。

**边界**：前两条由编译器保证，第三条要写代码的人保证；K 方向的越界值会进入求和，只有 mask 用改写前的下标时才成立。

### 锚点

只在用不到的组里不成立；对齐前提、组间边界、越界值无影响

## 15. 在 Triton kernel 里，下标经过 tl.where 后要恢复 16 字节的异步拷贝，常写 offs = tl.max_contiguous(tl.multiple_of(offs, 64), 64)。这两个函数各声明了什么？为什么只写其中一个不够？参数的值又有什么影响？

类型：技术问答 · 层级：机制 · 等级：A

适用范围：triton · 3.7.1

### 答案

**结论**：一次搬 16 字节要同时满足两件事：8 个元素一路加一，并且起点 16 字节对齐；max_contiguous 管前一件，multiple_of 管后一件。

- **max_contiguous**：声明张量能切成每 C 个一组、组内一路加一的段。
- **multiple_of**：声明每组第一个元素是 D 的倍数；整数下标按元素算，指针按字节算，tl.multiple_of(ptr, 16) 就是 16 字节对齐。
- **实测**：tl.where 之后只写其中一条，都退回逐元素同步读；两条都写成 64 才是 16 字节；任一个写成 4，一次只能搬 4 个 fp16，即 8 字节。

## 24. 解释不合并、不专用化的持久化矩阵乘为什么会在 tile 的边界上停下来。

类型：真实纠错 · 层级：机制 · 等级：A

第 09 课节点 5–6：比较 warp 专用化之后，搬运分区为什么不在 tile 边界停顿。

### 正确

根因是执行顺序：一批 warp 只有一条执行顺序，“发出下一个 tile 的读入”排在上一个 tile 的 epilogue 之后，所以 epilogue 期间路上没有数据，做完才发请求，然后还要等数据到。

### 错误

### 说明

**结论**：停顿的主要成分是等数据，不是算地址；算地址只是几条整数指令。

- **顺序**：tile i 的 K 循环 → 排空 → epilogue → tile i+1 的坐标 → 发出读入 → 等第一轮到达。
- **排空**：即使去掉排空，下一个 tile 的读入仍要等 epilogue 做完才能发，所以排空是表现，不是原因。

**边界**：flatten 把这句读入挪到前面，专用化给它单开一条执行顺序；两者解决的都是这个顺序问题。

## 38. 请用约 60–90 秒讲清：B 按行主序 \[K, N\] 存放时，怎样让 Triton 持久化矩阵乘中 B 的读入在 flatten 开与关时都是 16 字节、提前发出的异步拷贝？并说出你会怎样诊断。

类型：综合口述 · 层级：口述 · 等级：A

适用范围：triton · 3.7.1

### 参考回答

**结论**：关键是让编译器在 B 的连续方向 N 上看得出取值连续和对齐，并且这条信息出现在流水看得到的地方。

- **越界处理**：tl.where 把越界下标改成 0 会让取值连续度降到 1；要么只用 mask、不改写，要么改写后用 max_contiguous 和 multiple_of 两条声明补回。
- **合并后**：flatten 开时，tile 开头算的值经 scf.if 传出会丢掉声明，所以 N 方向的下标要在 K 循环里计算。
- **安全性**：声明在边界 tile 里不成立，但只发生在用不到的组里：对齐前提、组间边界、越界值被 mask 或丢弃。
- **诊断**：TTGIR 里没有 fp16 的同步 tt.load、PTX 的 cp.async 都是 16 字节，并且循环里 ttg.async_wait 的 num 大于 0。

**边界**：N 不是 16 的倍数时行首对不齐，怎么声明都只能逐元素读。

### 评分锚点

说出 tl.where 让取值连续度降为 1 的原因；说出两条声明各管什么；解释 flatten 后为什么要在 K 循环里算下标；说出声明在边界 tile 里不成立却安全的条件；给出异步与提前量两层诊断

## 39. 请用约 60–90 秒讲清：你怎样在 RTX 5090 上检验“持久化的优势随 K 增大而减小”这个预测？结果说明了什么，又没有说明什么？

类型：综合口述 · 层级：口述 · 等级：A

适用范围：triton · 3.7.1

### 参考回答

**结论**：用同一个 kernel 只改调度和 flatten 两个开关，交替测量、轮内相除、判据先写；结果支持方向，但收益主要来自 flatten，持久化本身很小。

- **设置**：块 128 × 128 × 64、3 个 stage、8 个 warp，M = N = 8192，K 取 128、512、2048；逐 tile 4096 个 CTA，持久 170 个。
- **结果**：持久化本身 1.023、1.002、1.000；flatten 1.184、1.035、0.987；总比值 1.213、1.037、0.987，随 K 下降。
- **解读**：“省掉重复发射”只得到很弱的支持；持久化本身那一列含分派、固定工作和调度方式三项，分不开。

**边界**：只测了一张卡、一组配置；K = 2048 时 flatten 的代价来源没有验证。

### 评分锚点

说出控制变量与两个开关；说出交替测量与轮内相除的目的；报出拆分后的两个因子并指出收益主要来自 flatten；说出持久化本身一列无法拆开的三项；说明结论的边界
