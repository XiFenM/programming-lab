## 01. 算法面试中，拿到一个看似熟悉、但条件还未说清的问题时，应优先澄清哪些约束，并怎样说明这些约束会改变候选算法？

类型：技术问答 · 层级：原子 · 等级：A

### 答案

**结论**：围绕数据、输出语义、访问方式和资源限制澄清条件；每确认一项，都要指出它会让什么方案可用、不可用或需要重新分析。

- **数据**：确认输入规模、值域、重复情况和已有顺序。规模影响计算成本能否接受；固定的小值域可能允许常数大小的状态；非递减顺序可能把判重转化为相邻比较。
- **输出语义**：确认结果是否必须精确、是否要求稳定性，以及返回值还是原下标。例如 Two Sum 若要返回两个不同原下标，方案必须保存足够的下标信息，不能只判断某个和值可达。
- **访问方式**：确认是可随机访问的数组还是单遍流，能否回看或重读。数组上的逐对枚举依赖重复访问；单遍流若不能重放，也没有缓存，就未必能执行原基线。
- **资源限制**：确认能否修改输入、允许多少额外空间。只读限制会阻止直接重排原输入；常数额外空间会排除随输入规模增长的历史存储，但要继续检查固定值域等条件是否允许其他方案。

**边界**：只追问会影响当前题目方案的条件，并把尚未确认的条件说成未知。背出分类名称，不能代替说明“这个条件为何影响算法”。

### 锚点

明确条件；说明它为何开启或排除方案

## 02. 向面试官解释 Two Sum：给定长度为 n 的数组 nums 和目标值 target，要找两个不同原下标，使对应元素之和等于 target。怎样把双层枚举基线的覆盖、成本和瓶颈讲清楚，而不只说它有两层循环？

类型：真实纠错 · 层级：机制 · 等级：A

### 场景

数组允许重复访问；基线固定第一个下标，再检查它后面的每个下标，找到符合要求的一对即可返回。

### 正确

说明每个不同下标对为何恰好被检查一次，再由比较次数得到最坏成本，最后指出对补数存在性的重复查询。

### 错误

第一个 n 在哪里，第二个 n 在哪里

### 说明

**结论**：双层枚举的解释应连起三个问题：为什么不会漏解、为什么最坏需要平方级工作量，以及哪些重复工作值得尝试消除。

- **覆盖**：外层下标 i 固定第一个元素，内层下标 j 只遍历其后的元素。任意两个不同下标都有唯一的较小者和较大者，因此所有合法无序下标对都会恰好出现一次；既不复用同一元素，也不把交换顺序后的同一对重复计算。

$$
0\le i<j<n,\qquad \mathrm{nums}_i+\mathrm{nums}_j=\mathrm{target}
$$

- **成本**：外层每前进一步，后面可配对的元素就少一个。若必须检查完全部候选，比较次数是从 n−1 到 1 的和；在每次取值、相加和比较为常数成本的前提下，这给出平方级最坏时间。

$$
\sum_{i=0}^{n-2}(n-1-i)=\frac{n(n-1)}{2}=\Theta(n^2)
$$

- **瓶颈**：每固定一个元素，都要重新扫描候选位置，查找“target 减去该元素”这个补数是否存在。下一步应验证：能否利用允许的额外状态、值域或顺序减少这些重复查询，同时仍满足原下标和互异下标要求。

**边界**：找到答案可以提前返回，因此某次输入不一定做完全部比较。仅数出两层循环，既没有证明覆盖完整，也没有证明存在符合题目约束的优化。

## 03. 为只读数组上的 Two Sum 寻找更快方案，题目只允许常数额外空间；检查过的排序方案和保存历史方案都违反约束。此时能否断言不存在比双层枚举更好的算法，应该怎样表述结论？

类型：真实纠错 · 层级：原子 · 等级：A

### 场景

需要找出和值等于 target 的两个不同原下标；目前排除的只是会重排原数组的排序方案，以及存储量随输入规模增长的历史保存方案。

### 正确

只能说这些已检查的候选不满足约束，目前尚未找到有效优化；不能由此断言所有优化都不存在。

### 错误

目前就没有满足所有条件的优化方案了

### 说明

**结论**：“当前候选受阻”是有限检查的结果；“不存在更优算法”是对所有允许算法的断言，两者所需证据不同。

- **已知证据**：把被排除的具体方案与约束对应起来：直接重排原数组违反只读要求，保存随输入增多的历史记录违反常数额外空间要求。不要把某个方案被排除扩大成整个思路类别一律不可用。
- **仍待检查**：继续区分尚未确认或利用的条件，例如值域是否固定、输入是否已有顺序、允许怎样访问。固定小值域就可能重新允许固定大小的状态，所以两个常见方案失败并没有穷尽所有可能。
- **可用表述**：可以说：“我目前检查的这两个方案分别违反只读和空间约束，暂时没有找到满足全部条件的优化；接下来需要核对值域、顺序和访问条件。”

**边界**：要宣称双层枚举已经最优，或不存在更快方案，需要在明确的输入条件和计算模型下给出相应下界论证；“我暂时想不到”不能替代证明。

## 04. 判断一批 ID 是否出现重复时，原方案在数组上逐对比较。若输入改成只能读一遍、不能回放且没有保存全部历史的 ID 流，为什么不能直接沿用这套双层枚举基线？

类型：技术问答 · 层级：原子 · 等级：A

### 答案

**结论**：原基线依赖能反复取得各个元素；单遍流改变了访问权限，所以必须先确认算法还能执行，再讨论它的时间复杂度。

- **数组依赖**：在数组中，固定一个 ID 后可以访问其他位置进行比较，换下一个 ID 时还可以再次访问这些位置。逐对枚举的正确性和执行过程都依赖这种重复访问。
- **条件变化**：单遍流的元素消费后，既不能回放，又没有完整历史缓存；当后面的 ID 到达时，先前的任意 ID 已经不一定可取。因此不能仅把原数组代码的输入类型换成流，就继续完成所有逐对比较。
- **分析顺序**：应先明确允许保存什么状态、能否重读，以及流是否具有顺序保证，再判断可采用的判重方法。原数组算法的复杂度标签不能证明它在新访问模型中可执行。

**边界**：如果允许缓存或重放，逐对比较的可行性可能改变，但必须重新计入缓存空间和读取权限。这里否定的是直接复用原基线，并未证明单遍流无法判重。

### 锚点

访问条件改变 → 重查基线可执行性 → 再算成本

### 来源

算法 01 日志 · 数组到单遍流的转折

## 05. 一条只能读取一遍的 ID 流保证按非递减顺序到达，目标是精确判断是否出现重复 ID。为什么只保留前一个值就足够，算法的时间和额外空间成本是什么？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：非递减顺序保证重复值连续出现，因此逐项比较相邻 ID 即可；发现相等就能确认重复，不需要保存全部已见值。

- **完整性依据**：设两个位置的 ID 都是 x，夹在它们之间的任一值为 y。非递减性同时限制 y 不小于前面的 x，也不大于后面的 x，所以 y 只能等于 x；只要出现重复，就一定存在一对相邻重复。

$$
x\le y\le x\quad\Longrightarrow\quad y=x
$$

- **扫描机制**：已有前一个值时，将新到达的 ID 与它比较；相等则报告重复，不等则用当前值更新前值并继续。相邻相等显然是真重复，而上面的顺序证明保证这个检查不会漏掉重复。
- **成本来源**：设 n 为 ID 总数，最坏需要读完整条流，每次只做常数次比较和更新；保存的前值及必要状态数量不随 n 增长。

$$
T(n)=O(n),\qquad S_{\mathrm{extra}}(n)=O(1)
$$

**边界**：任意顺序流中的相同 ID 可能被其他值隔开，相邻比较就会漏检。本卡说明已确认的判重机制；空流、首元素初始化和哨兵冲突仍属于日志列出的后续实现边界。

### 锚点

非递减保证重复相邻；前值比较即可检出

算法 01 日志 · 非递减流迁移

## 06. Two Sum 要求在数组中选两个不同下标，使其元素和等于给定 target；已知每个元素只能是 0、1、2。仅凭这个值域，能否断言合法输入的 target 只能是 0 到 4？

类型：真实纠错 · 层级：原子 · 等级：A

### 场景

需要区分“两个元素能够得到的和值范围”与“题目允许传入的 target 范围”，并检查题目是否保证有解。

### 正确

仅凭元素值域，只能限制可达和值；再有“保证存在一对解”的前提，才能由此推出 target 在 0 到 4 内。

### 错误

target 也只可能有 0、1、2、3、4……共 5 种情况

### 说明

**结论**：元素值域约束的是两数相加可能产生什么结果，不会自动把范围之外的 target 变成非法输入。

- **推导前提**：两个元素都只能取 0、1、2，因此任意一对的和值只能落在 0 到 4。若题目保证有解，target 必须等于其中某对的和值，才可据此限制 target。

$$
\mathrm{nums}_i,\mathrm{nums}_j\in\{0,1,2\}\quad\Longrightarrow\quad 0\le\mathrm{nums}_i+\mathrm{nums}_j\le4
$$

- **范围外例子**：例如题目没有限制 target、也没有保证有解时，传入 target 为 5 与元素值域并不矛盾；这个输入只是不存在符合要求的一对元素。

**边界**：target 落在 0 到 4 内也不保证当前数组有解，还要看实际有哪些元素，以及能否使用两个不同下标。若题目另行规定 target 范围，则应依据那条明确约束。

## 07. Two Sum 的输入是长度为 n 的只读数组，元素仅取固定的 0、1、2；给定 target，要返回一对不同的原下标，且只允许常数额外空间。怎样用一次扫描构造完整方案，并避免同一元素被用两次？

类型：技术问答 · 层级：机制 · 等级：A

### 答案

**结论**：为三个可能的值各保存至多两个不同原下标，再检查所有无序值对。固定值域让状态数量保持常数，保存两个下标则能处理两个相同值配对的情况。

- **保留状态**：扫描原数组时，按元素值记录下标；某个值已有两个下标后，无须继续保存它的更多出现位置。题目只要求返回一对解，所以每个值的前两个不同下标足以支持任意一次同值或异值配对。
- **完整枚举**：扫描后检查下面六个无序值对，只考虑和值等于 target 的候选。它们覆盖三个值允许的全部配对，尤其不能漏掉零和二这一对。

$$
(0,0),\ (0,1),\ (0,2),\ (1,1),\ (1,2),\ (2,2)
$$

- **检查与返回**：异值配对要求两个值各有一个已记录下标；同值配对要求该值确实有两个不同下标。条件成立就返回对应原下标，不能把一个下标使用两次；若六对都不成立，就没有符合要求的解。
- **成本与只读**：一次扫描的工作量随数组长度增长；最多保存六个下标，后续也只检查六个值对。全程读取原数组，不需要改变元素顺序。

$$
T(n)=O(n),\qquad S_{\mathrm{extra}}(n)=O(1)
$$

**边界**：常数空间结论依赖值域固定为这三个值，不能直接推广到值域随输入增长的情况。本方案返回一对解；它没有承诺保存或输出所有下标对。

### 锚点

每值两下标；六种值对；异值各一、同值需二

算法 01 日志 · 固定值域纠错

## 08. 一次算法面试练习中，候选人把某道题的约束、基线和优化思路解释清楚了，但尚未实际编写或调试代码。评价者能据此肯定哪些能力，怎样避免直接推断其整体岗位胜任？

类型：技术问答 · 层级：原子 · 等级：A

### 答案

**结论**：评价范围应与实际观察到的表现一致：可以肯定本题中展示的分析与表达，同时明确实现、调试和其他岗位能力仍未得到观察。

- **已观察**：具体陈述证据，例如能澄清影响算法的约束，说明基线的完整性和成本，并把候选方案与约束对应。这样评价有明确对象，别人也能检查依据。
- **未观察**：没有实际编码或调试，就不能把思路清楚自动当成实现正确、调试熟练的证据；本题也没有展示系统设计能力。应将这些标为尚未观察，而不是直接判定优秀或不足。
- **评价示例**：例如：“本题的约束澄清和方案解释已有清楚证据；代码实现、调试及系统设计尚未观察，暂不据此判断整体岗位胜任。”

**边界**：单题的局部好表现可以支持局部判断，不能直接覆盖整个岗位所需能力。扩大结论范围，需要补充相应范围的实际证据。

### 锚点

证据覆盖到哪里，评价就说到哪里

## 09. 向面试官说明 Two Sum 的解题过程：给定数组和 target，要求返回两个不同原下标，使元素和等于 target；访问方式、修改权限和空间限制尚待澄清。请用 45–90 秒说明如何从约束走到可验证基线、筛选优化，并在候选受阻时给出有依据的结论。

类型：综合口述 · 层级：口述 · 等级：A

### 参考回答

**结论**：我会先确认哪些操作被允许，再给出能验证的基线，针对重复工作提出候选，并让最终结论严格对应已检查的证据。

- **澄清**：先问输入规模、值域和顺序，确认是否返回原下标、能否随机访问或重读、能否修改输入，以及额外空间上限。这些答案分别决定成本是否可接受、基线能否执行，以及排序或保存历史是否可用。
- **基线**：若输入允许重复访问，基线就是枚举所有不同下标的无序对。只让第二个下标位于第一个之后，每对恰好检查一次，因此不会漏掉答案；最坏比较次数随 n 的平方增长，其中 n 是数组长度。
- **筛选**：瓶颈是固定一个元素后反复查找补数。接下来逐项核对候选：重排输入是否允许，保存历史是否超出空间限制，固定值域或已有顺序能否提供其他方向，而不是只报一个熟悉算法的名字。

**边界**：如果目前候选都违反约束，我会说尚未找到有效优化，并指出还需核对的条件；排除几个候选不等于证明基线最优，没有相应下界论证就不宣称所有更快算法都不存在。

### 评分锚点

说清数据、输出、访问和资源条件，并解释它们怎样影响方案；基线可执行，且说明不同下标对的完整覆盖与最坏成本；从重复补数查询出发，把每个优化候选逐项对照约束；候选受阻时保留未知，区分暂未找到优化与已证明下界
