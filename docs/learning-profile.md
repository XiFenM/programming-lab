# 学习者画像与讲解深度

本页是 `guide-learning` 的只读学习者偏好事实，Triton 与算法面试两条课程共用。它只描述学习者和讲解偏好，
不保存课程状态、授权或进度；讲解、提问、练习与结课的行为由中央 Skill 定义。

## 背景与目标

- AI Infra 工程师，从事非 NV 加速器上的 PyTorch／vLLM 适配、通信与性能优化；具体经历以学习者已提供的
  内容为准，不杜撰。
- 两条课程都服务于 AI 框架工程师岗位的学习与面试。学习者于 2026-09-28 明确要求以理解为中心：讲清机制、
  设计理由和真实实现，检查题考理解而不是计算。
  - Triton 官方教程：理解 kernel 的分块、存储层次、精度与性能取舍，并能实现和验证；
  - 算法面试：独立处理常见题型，并能清楚表达约束、基线、优化思路、正确性与复杂度。

## 目标深度

- 默认讲到中央讲解标准的第 5 层（表达与迁移）。
- Triton 课在设计理由之外，要落到本仓库固定版本的教程源码，以及目标需要时可复现的测量。
- 算法课强调从约束到基线再到优化的推导、循环不变量或状态定义，以及复杂度论证。
- 每门课的综合验收至少包含一道 60–90 秒的口述题：Triton 课讲清一个 kernel 的整体数据流与取舍，算法课按
  面试节奏讲完一道题。

## 讲解偏好

- 先给课程全貌和全流程骨架，再进入局部推导。学习者在 2026-09-24 的 Triton 第 06 课指出"常规情况下，我有
  能力理解通用公式"。
- 符号先行：先定义符号、维度与单位，再按需代入数字；不同维度即使取值相同也用不同符号，例如 `BLOCK_M` 与
  `BLOCK_N`。
- 节点依赖的 Triton API、dtype 或抽象，先讲清语义和选择理由，再读用到它们的代码。

## 检查题偏好

- 优先考理解：解释为什么、比较取舍、从现象诊断、改条件预测、迁移到新题或新 kernel、口述。
- 计算题只用于估算本身有意义的场合，例如访存量、算术强度、寄存器与共享内存占用、时间与空间复杂度，并要求
  解释结论。
- 算法课需要实现时，按 [LeetCode 练习约定](leetcode-practice-conventions.md) 放置题解与测试。
